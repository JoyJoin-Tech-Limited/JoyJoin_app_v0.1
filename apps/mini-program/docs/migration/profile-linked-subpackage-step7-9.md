## 1. Step 7 — `usePageTTI` Hook

### New file: `src/hooks/usePageTTI.ts`

A small, self-contained hook that measures time-to-first-interactive (TTI) for mini-program pages.

**Design**
- Records start time on `useLoad` (falls back to `useDidShow` if `useLoad` is skipped, e.g. H5).
- Reports once when the page becomes ready:
  - If no `ready` flag is supplied, reports on the first effect flush after mount.
  - If `ready` is supplied, reports on the first transition to `true`.
- Defers reporting with `setTimeout(..., 0)` so it never blocks render.
- Logs via `logInfo` (primary channel).
- Falls back to `wx.reportAnalytics('page_tti', ...)` when available.
- Cold/warm heuristic uses app-launch timestamp (best-effort via `Taro.getAppBaseInfo().startTime`, else `Date.now()` on first use) and a 3-second cold-start window.

**Budgets**

| Start type | Budget |
|------------|--------|
| Cold | ≤ 2000 ms |
| Warm / preloaded | ≤ 800 ms |

**Public API**

```typescript
usePageTTI({ pageName: string; ready?: boolean; disabled?: boolean }): void
```

### Integration into migrated pages

| Page | Ready condition | Notes |
|------|-----------------|-------|
| `subpackages/profile-linked/terms/index.tsx` | none (static page) | Reports on mount. |
| `subpackages/profile-linked/invite/index.tsx` | `!authLoading && !isLoading` | Waits for auth + referral stats. |
| `subpackages/profile-linked/rewards/index.tsx` | `!authLoading && !couponsQuery.isLoading` | Waits for auth + primary coupons query. |
| `subpackages/profile-linked/edit-profile/index.tsx` | `!authLoading && !isInitializing` | Waits for auth gate and local initialization effect. |

## 5. Notes / Risks

- `usePageTTI` is additive and does not block render. It uses `setTimeout(..., 0)` to defer reporting.
- The hook guards `wx.reportAnalytics` with `typeof wx !== 'undefined'`, so H5/browser builds are safe.
- Cold/warm classification is a heuristic. Real device validation can tune `COLD_START_WINDOW_MS` if needed.
- The main package is still above the 1.80 MB guideline. Reaching it requires the existing CDN asset strategy (move Lovart/promo/matching/empty-state assets to CDN), not further subpackage splitting.
