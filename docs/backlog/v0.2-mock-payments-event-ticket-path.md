# [v0.2] MOCK_PAYMENTS not honored on the event-ticket payment path

**Status:** Backlog | **Priority:** High (blocks local/staging smoke of the main paid funnel) | **Labels:** v0.2, payments, mini-program, testing

---

## Goal

Make `MOCK_PAYMENTS=true` work end-to-end for the pool-registration → event-ticket-payment flow, so local dev and staging smoke tests of the primary paid funnel never invoke real WeChat Pay — matching the behavior AGENTS.md §3 already claims ("the mini-program skips `Taro.requestPayment()`"), which currently only holds for the blind-box path.

## Current State (verified 2026-08-17)

- `MOCK_PAYMENTS=true` is honored only on `POST /api/payments/miniprogram/create` (`apps/server/src/routes/domains/payments.ts:732-778`), which returns `mock: true` on an instantly-`completed` order.
- Only the blind-box client checks the flag: `apps/mini-program/src/pages/payments/blind-box-payment/index.tsx:705` skips `Taro.requestPayment()` when `paymentIntent.mock` is set.
- The event-ticket path goes through `POST /api/event-pools/:id/register-with-payment` (`apps/server/src/routes/userEventPools.ts:960`) which has **no mock branch**, and `apps/mini-program/src/pages/payments/event-ticket-payment/index.tsx` never checks a `mock` flag — it always calls `Taro.requestPayment()` and then polls `/api/payments/status/:orderId`.
- Net effect: with `APP_MODE=staging` + `MOCK_PAYMENTS=true` + `TEST_PAYMENT_PRICE_IN_CENTS=1`, the blind-box flow is free, but the main pool-registration paid flow still opens the real WeChat Pay sheet.

## Required Work

### 1. Server: mock branch in `register-with-payment`
- In `apps/server/src/routes/userEventPools.ts` (`register-with-payment` handler), when `MOCK_PAYMENTS=true`, create the order as instantly-paid (`status: completed`, `mock: true`) and run the same fulfillment path as a real payment callback (registration created, caches invalidated, shell cache invalidated) — reuse the existing fulfillment helper rather than duplicating it.
- Keep the mock branch gated exactly like the existing `payments.ts` one (never in production; `APP_MODE`/`NODE_ENV` guard parity).

### 2. Mini-program: skip `Taro.requestPayment()` on `mock: true`
- In `event-ticket-payment/index.tsx` `handlePay`, mirror the blind-box pattern: if the create-order response carries `mock: true`, skip `Taro.requestPayment()` and go straight to the verify/success path (registration already fulfilled server-side; a single status fetch or direct success transition is enough — no 20×1s poll).

### 3. Verification
- Local smoke per AGENTS.md §3 recipe (`.env`: `APP_MODE=staging`, `PAYMENTS_ENABLED=true`, `TEST_PAYMENT_PRICE_IN_CENTS=1`, `MOCK_PAYMENTS=true`): register into a pool without entitlement → payment page → pay → success → registration visible, no WeChat Pay sheet.
- Add/extend a server test covering the mock branch of `register-with-payment` (mirror the existing `payments.ts` mock tests if any).

## Out of Scope
- Real WeChat Pay behavior changes (untouched).
- The separate `MOCK_PAYMENTS` semantics for refunds.
- AGENTS.md §3 wording is correct once this lands — no doc change needed beyond closing this item.

## Dependencies
- None. Server + mini-program changes can ship together; no schema or migration work.
