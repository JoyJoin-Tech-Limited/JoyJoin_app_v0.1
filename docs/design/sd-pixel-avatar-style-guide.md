# SD 像素形象 · 美术风格规范（绑定文档）

> 日期：2026-08-07
> 状态：Phase A 定稿。本文档仍是 SD 像素形象与集结房间像素场景的**风格权威**；后续所有 Lovart brief、手绘修像素、验收检查都以本文档为准。修改本文档需要 founder + 品牌评审双签。
> 适用范围：SD 像素形象（12 原型）及其未来衍生的分享物料；集结房间场景美术仍遵循本规范，但**角色层已于 2026-08-10 切换为复用现有 V2 纸娃娃 + 装备体系**，不再在房间内新建 SD 小人。
> 关联文档：`docs/product/gathering-room-prd.md`、`docs/design/lovart-brief-sd-avatar-*.md`、`docs/design/lovart-brief-gathering-room.md`、V2 高个纸娃娃管线 `assets-source/profile-pixel-v2/README.md`。

## 0. 定位一句话

东方同人（Touhou-doujin）气质的 SD 像素小人，但**柔化**——彩色描边、暖光、克制配色，让像素读起来是「精致的小世界」而不是「硬核游戏素材」。它曾是 V2 高个纸娃娃的 Q 版分身方案，最终未被集结房间采用；SD 规范保留给未来可能启用的紧凑头像/全局图标场景，不取代 V2。

## 1. 七条冻结设计令牌（Design Tokens）

以下 7 条为**硬约束**，任何一张 SD 形象或场景资产违反任意一条即不可入库。

### T1. 受限色板（≤32 色）

- 每张资产（单个角色 / 单层场景）用色 **≤32 色**，含描边色与阴影色。
- 场景美术中**必须出现**三个品牌色，把像素场景与暖白/紫色主 UI 缝合起来：
  - 品牌紫 `#8B5CF6` —— 出现在灯罩上
  - 暖珊瑚 `#FF9B85` —— 出现在桌布上
  - 暖米 `#F5F1E8` —— 出现在墙面
- 角色色块**延伸现有 12 原型色**（见 §3 表，源自 `packages/shared/src/archetypeColors.ts` 的采样色），**禁止引入新的高饱和色**。需要新色时，先在原型色上做明度/饱和度微调，再进色板。

### T2. 彩色描边规则（风格核心差异点）

- 所有描边 **1px**。
- 描边色 = **该色块基色同色相、明度压到 30%** 的颜色（例：基色 `#CB8783` → 描边 ≈ `hsl(3, 40%, 30%)`）。
- **永远禁止纯黑描边。** 这是与硬核同人像素风的关键区别：黑色描边 = 游戏素材感；同色相深色描边 = 柔和、高级、与品牌暖调一致。
- 高光同理：受光侧 1px 高光用基色提亮（明度 +20~25%），不用纯白。

### T3. 网格与身高

- 场景按 **16×16px 瓦片网格**绘制；所有家具、门窗对齐网格。
- 角色身高 **100–130px**（二头身 SD：头部约占 1/2），同一房间内所有角色共用同一身高基准线。
- **脚底必须落在瓦片网格线上**——角色站在地上，不漂浮。

### T4. 单一暖主光

- 全场**只有一盏暖色主灯**（房间主灯，从上方打下）；所有角色、家具共享同一个光照方向。
- 每个物体/角色的投影 = **1 个椭圆地面投影** + 受光侧 **1px 高光**，仅此而已。
- **禁止复杂 shading**（不做多层渐变、不做环境光遮蔽、不做轮廓光）。像素的体积感来自色块形状，不来自阴影层数。

### T5. 视角

- 场景：**45° 俯视**（top-down 斜视角，看得到桌面与地面的纵深）。
- 角色：**正面朝向**绘制（front-facing）。4 方向转身图（turnarounds）**明确延期**，MVP 不做行走。

### T6. 整数倍导出

- 角色资产交付**预缩放好的 4 档尺寸：96 / 64 / 48 / 32px**，每档单独做像素级清理（per-size pixel cleanup，逐档修边、修眼、修特征），不允许只交一稿大图让程序缩。
- **运行时禁止非整数倍缩放。** 微信渲染非整数缩放会做平滑插值，1px 描边会被糊掉——像素风全部质感随之消失。布局需要中间尺寸时，改布局，不改缩放。

### T7. 风格防火墙

- 像素美术**只允许出现在**：集结房间场景、未来被启用的 SD 形象本体、以及由二者衍生的分享物料（合影卡片、记忆页定格图）。
- 主 UI **永远不用**像素字体、像素按钮、像素边框等游戏化 chrome。房间外的一切界面沿用现有暖白/紫色设计系统。像素是房间里的小世界，不是 App 的皮肤。

## 2. 动物翻译规则（Species Translation）

把 12 个动物原型翻译成 SD 像素小人时，统一遵守：

1. **物种特征即「发型」。** 物种识别主要靠头部轮廓完成，如同发型之于人脸。
2. **每个原型只保留：1 个招牌特征（放大到符号级）+ 1 个次要特征。** 其余全部舍弃。符号级 = 3 秒看图说不出品种也能说出物种。
3. **数量符号化：** 章鱼触手 → **4 条**；蜘蛛腿 → **4 条**。
4. **象鼻**：短且上翘（小象感），不做写实长鼻。
5. **鸡冠**：必须从帽子开口中露出来（见 T-headwear 硬规则）。
6. **全局硬规则 · 头部装备不得完全遮盖招牌物种特征。** 任何帽子/头饰必须给招牌特征留开口或让位（鸡冠穿帽口、猫耳顶出帽檐、考拉圆耳露两侧）。装备再好看，遮住物种特征就一票否决。
7. **统一像素眼：** 12 个原型共用同一套眼型——大眼 + 1px 高光点。物种差异靠轮廓与配色，不靠眼型差异。
8. **装备可见层只有 2 层：** 头部配饰 + 上装色块。下装/鞋不做（SD 二头身下半身面积极小，做了也读不出）。

## 4. 验收标准（Validation）

每张 SD 形象入库前按顺序过以下四关：

1. **48px · 3 秒物种识别测试：** 将 48px 档形象拿给 **5 位非团队成员**看，每人限时 3 秒说出动物物种。5/5 答对为通过；任何一人犹豫或答错即回炉（优先放大招牌特征，不是加细节）。
2. **易混簇并排测试：** cat / fox / corgi 三张 48px 并排，同样 5 位非团队成员，3 秒内逐一指认，全对为通过。
3. **真机不糊检查：** 在微信开发者工具 + 至少一台真机上以 4 档尺寸逐档查看，1px 描边与眼睛高光必须清晰锐利；发现糊边先查是否发生了非整数倍缩放（违反 T6）。
4. **「是同一个角色吗」测试：** SD 形象与 V2 高个纸娃娃（`assets-source/profile-pixel-v2/<archetype>/atlas-source.png`）并排展示，5 位看过 V2 的用户判断「是不是同一个角色」。4/5 认为「是」为通过。配色与招牌特征必须与 V2 一致。

## 5. 制作顺序：先打最难的

**用最难的原型做验证 pilot，不用最容易的。** 第一个做的是 `octopus`（脑洞章鱼）：触手符号化、二头身比例、彩色描边三条最难的规则同时在它身上承压。章鱼过了验收，其余 11 个都是降维；反过来用猫做 pilot，过了也证明不了体系成立。

顺序：**octopus（pilot，定风格帧）→ rooster（验证鸡冠穿帽规则）→ cat（验证易混簇基线）→ 其余 9 个批量**。

## 6. 与既有系统的关系

- **V2 高个纸娃娃不动。** SD 是独立资产族，配色与招牌特征向 V2 看齐（「同一角色」测试），但文件、管线、运行时互不复用。
- **装备体系复用现有 inventory**（`equipmentRewardsEnabled` 那套），但 SD 形象只渲染 2 层（头部配饰 + 上装色块）。映射关系在 SD 被实际启用时定义，不在本文档；集结房间已改复用 V2 纸娃娃 + 装备体系。
- **分享物料**（合影、记忆页定格）由房间视口截图/合成派生，沿用既有 Canvas poster 管线约束（DPR ≤2、CDN PNG 兜底等，见 `docs/agent-context/mini-program-assets.md`）。
