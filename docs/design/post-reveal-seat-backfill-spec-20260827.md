# 揭示后空位回补 · 设计规格（定稿）

> 日期：2026-08-27
> 状态：产品 + 商业化方向已定稿，可直接交付 PRD / 实现 agent
> 输入：PM 全量提案（已裁剪）+ 商业化决策备忘录（候补定价）+ owner 三条裁剪指令
> 适用范围：付费活动池（event pools），匹配揭示（match reveal）之后到活动开场之间的空位生命周期

---

## 0. 锁定产品决策（owner 定稿）

1. **只做一个回补来源：同一池子的已报名用户。** 候补候选 = 匹配后未排上桌的同池报名用户（顺延人群）。不做跨池迁移、不做运营定向邀请自动化（`post_match` 邀请轨道保持现状，仅作 admin 手动兜底）。
2. **不做处罚阶梯。** 唯一的爽约威慑 = **匹配揭示后取消不退款**。不建爽约记录表、不做排桌权重、不做暂停报名、不做免责卡/申诉队列。
3. **不过度建设。** 全部新基础设施收敛为：一个候补状态、一个认领端点、一批通知触发、两个 feature flag。状态机收敛为 `filled → open → claimed | released`。
4. **候补定价：免费候补，认领成功才扣全款 ¥88（单场局票价）。** 不做半价/任何折扣（决策依据见 §4）。候补价格必须走 DB `pricing_settings` 配置源，不硬编码。

### 被明确否决的方案（防复活）

| 否决项 | 否决理由 |
|---|---|
| 半价（¥44）候补 | 蚕食 ¥88 正价报名（价差大到改变购票行为）；砸穿价格锚（`seed_pricing_plans_20260805.sql:18` 明确 no fake strikethrough）；双边公平感知风险。候补天然"不保证有座"，不确定性本身就是防蚕食防火墙，不需要折扣 |
| 处罚阶梯 / 排桌权重 / 暂停报名 | 复杂度与威慑收益不成比例；不退款 forfeiture 已是完整威慑 |
| Tier B 硬编码折扣价、Tier C 自动化定向邀请 | 超出"同池已报名用户"边界 |
| 顺序报价（30min × 3 轮） | 解决了一个不需要解决的竞态；T-4h 窗口内根本走不完 |
| 缩组补偿 credits | 诱发套利（合伙取消刷补偿）；诚实通知已足够 |
| 候补价硬编码 | 违反 DB `pricing_settings` 单一配置源原则 |

## 1. 问题定义

**当前现实（已验证）：** `DELETE /api/pool-registrations/:id`（`apps/server/src/routes/domains/userEventPools.ts:1363`）只删行 + 计数器减一。匹配揭示后取消：
- 不从已成形的组里移除该成员——其余成员到场才发现少了人（silent hole）
- 不触发任何回补、不通知组员、不通知运营
- 支付端无任何 forfeiture 后果

**一句话任务：** 揭示后的每个席位，要么开场时被填满，要么组被诚实、优雅地缩容；退出者的票款不退，空出的席位自动从同池顺延人群中补回。

## 2. 机制规格

### 2.1 时间边界（全部锚定 `events.date_time`）

| 边界 | 规则 |
|---|---|
| 匹配揭示前 | 取消 = 按现有政策退款（现状不变） |
| 匹配揭示后 | 取消 = **票款不退（forfeiture）**；取消流程必须前置一行警示文案（见 §5.1） |
| 集结房间（gathering room）开放 | **候补永久关闭。** 冷入场者闯进已暖场的房间对双方都是降级体验，宁可缩组 |
| 活动开场 | 候补队列清空，未命中候补自动退款（挂现有 auto-refund pipeline） |

注：首版**不做** T-24h/T-4h 确认触点。不退款政策本身是主威慑；若 Phase 0 数据显示揭示后取消率仍高，再在 Phase 2 补一个确认触点（见 §7）。

### 2.2 席位状态机

```
FILLED
  └─ 成员在揭示后取消 ──────────────▶ OPEN（票款不退；组员+运营收到通知）

OPEN
  ├─ 候补用户认领（FCFS，原子守卫）─▶ CLAIMED（扣款 ¥88，入组，组员收到通知）
  └─ 房间开放前无人认领 ────────────▶ RELEASED

RELEASED
  ├─ 组剩余 ≥ 4 人 ─────────────────▶ GROUP_SHRUNK（诚实通知，无补偿）
  └─ 组剩余 < 4 人 ─────────────────▶ GROUP_COLLAPSED
                                        → 整局顺延 → 现有「场次未成行」
                                          auto-refund pipeline（Trigger B 模式）
```

测试池（`is_test_pool=true`）跳过整个生命周期（沿用既有容量门豁免模式——机器人不会放鸽子）。

### 2.3 候补池（Phase 1）

**入队：** 匹配落定、用户被顺延（unmatched）的瞬间，退款动作改为二选一：
- 「直接退款」→ 走现有 Trigger B
- 「留个候补席位，排上再付款」→ 退款挂起（`refund_pending_waitlist`），进入本池候补队列；**占位免费**

**出队（任一先到）：** 认领成功 / 房间开放（队列清空，挂起的退款自动释放）/ 用户主动退出候补（退款立即释放）。

**认领（FCFS，先到先得）：**
- 席位 OPEN 时，向该池**全部**候补用户推送通知（「这桌有席位空出来了」）
- 第一个点「认领席位」的成交；其余人看到「手慢啦，席位已被认领」，留在队列等下一个空位
- 竞态守卫：单个原子 `UPDATE ... WHERE seat_status = 'open'`（或等价行锁），DB 层保证只有一个赢家；**不做**顺序报价、TTL 队列、报价状态机

**质量门（便宜且必须）：** 只对匹配时已达可排质量线的顺延用户开放候补（在 formation 中因 R1/性别地板等硬约束落败的用户本来也坐不进这桌）。认领时不重跑评分——formation 阶段已经评估过这批人对这个池子的适配，同池同约束直接复用结论。**不放宽任何阈值，不设 relaxation tier。**

**认领成功后的写入序列：** 创建支付订单（¥88，`pricing_settings` 单场局票价）→ 支付确认 → 入组（写组成员关系）→ 场地容量复核（只填原空位，构造上 ≤ 原容量，复核为防御性断言）→ 加入集结房间 → 组员通知（见 §5.2）。

**duo 边界：** 揭示后 duo 之一取消，按"双人原子单元"处理——两个席位一起空出（留下的伙伴可选择一起退出并同样不退款，或单独留下）。2 席位空位可被一对绑定 duo 认领，或被两个独立单人先后认领。首版不为此做任何特殊 UI，复用 FCFS。

### 2.4 缩组与塌组

- **缩组（≥4 人）：** 局照常进行。释放时刻主动通知剩余成员（不要让他们到场才发现）：「有位伙伴临时有事来不了，今晚是温馨的 5 人局」。**无补偿。**
- **塌组（<4 人）：** 社交密度不可行，触发整局顺延 → **复用**现有「场次未成行」auto-refund pipeline（`apps/server/src/services/autoRefundService.ts`，Trigger B 模式），不与不退款政策冲突（塌组是平台侧决定，退款给的是留下的人，不是退出的人）。

## 3. 不退款政策（Phase 0 核心）

- **规则：** 匹配揭示前取消 = 正常退款；揭示后取消或缺席 = 票款不退。
- **执行点：** 取消流程（`/api/pool-registrations/:id` DELETE 前端入口）在揭示后状态下前置确认弹层，警示文案见 §5.1；服务端按注册 `matchStatus` / 揭示时间戳判定是否退款。
- **边界 case：** 池取消 / 场次未成行 / 塌组 = 平台责任，照常退款（现有 Trigger A/B 不变）。不退款只罚"用户主动退出且局照常进行"的情形。
- **条款同步：** `packages/shared/src/legal/joyjoinTermsZh.ts` 退款与取消条款需同步更新（揭示后不退），并由法务过目。

## 4. 商业化决策依据（候补定价备忘）

**决策：免费候补，认领成功扣全款 ¥88；永不打折。**

1. **物理层：** 临开场空位是易腐库存，平台边际成本≈0，且退出者 ¥88 已 forfeiture 落袋——候补收入是纯增量。这是唯一支持折扣的论据，且被需求层完败。
2. **需求层：** 候补相对早报名是严格更差的产品（不确定有座、通知晚、无组预览、冷入场）。两个同价产品中没人会为省钱选更差的——**不确定性本身就是防蚕食防火墙**，不需要折扣。错过窗口的用户对「能不能赶上这场」敏感，对 ¥88 vs ¥44 不敏感。
3. **价格锚：** ¥88 单场局票锚点不可砸；悦聚月卡有效单价 ¥16.3/场（¥98/6场），¥44 会在月卡与单场之间制造尴尬新锚点。repo 定价正典明确反对折扣信号（`original_price_in_cents stays NULL`）。
4. **降级路径：** 若认领率 <30%，才允许上有界激励（¥10 减免或小额小悦券），走 `pricing_settings` 配置 + feature flag 灰度，不硬编码百分比折扣。
5. **文案纪律：** 候补只说「排上再付款」的确定性，禁止出现 优惠/折扣/半价/捡漏 类词（🔴 硬规则）。

## 5. UX 面（小程序）

全部文案遵守 `docs/copy/brand-copy-strategy.md`：排桌/席位/轮桌畅聊词汇，禁出现 匹配/社交/撮合/AI；无内联 emoji；候补身份对组员永远不可见（无 stigma 标签）。

### 5.1 取消流程（揭示后）

- 确认弹层：「现在取消将不退还报名费。这桌的伙伴们会收到通知哦。」— 两个按钮：「再想想」（默认聚焦）/「确认取消」。
- 取消成功后 toast：「已取消，期待下次见到你」。

### 5.2 matching-status / 组详情

- 空位 OPEN：组员看到组视图该席位变为中性占位（「排桌中…」复用现有 pending 视觉），**不暴露**是谁退出。
- 认领成功：组员收到一条温暖通知：「今晚有位新伙伴加入，一起期待吧」。组视图新成员正常展示，与原生成员完全同权。
- 缩组：「有位伙伴临时有事来不了，今晚是温馨的 5 人局」。
- 塌组：复用现有「场次未成行」退款通知 + 「已为你优先保留下一场的排桌资格」（首版仅为文案，不做实际优先权逻辑）。

### 5.3 顺延时刻（Phase 1 候补入队）

- 未排上页二选一：「直接退款」/「留个候补席位，排上再付款」（副文案：「候补不上，钱自动退回」）。
- 候补中的状态卡：场次信息 + 「有席位空出会第一时间通知你」+「退出候补并退款」入口。
- 空位通知：push + 站内信「这桌有席位空出来了，先到先得」→ 落地认领页（一屏：时间/区域/局型/¥88/「认领席位」CTA）。
- 认领失败：「手慢啦，席位已被认领。再有空位还会通知你」。
- 队列清空（房间开放）：「这次没能排上，报名费已退回」（挂起退款自动释放）。

### 5.4 通知类型（新增，走现有 `createNotification` + `eventBroadcast`）

`seat_vacated_group_notice`（组员）、`backfill_available`（候补队列）、`backfill_claimed`（认领者+组员）、`backfill_missed`（未抢到者）、`waitlist_expired_refund`（队列清空）、`group_shrunk`、`group_collapsed_refund`（复用现有文案模式）。

### 5.5 Admin / 运营

- 首版**不建**席位面板。空位 OPEN 与 3 次认领失败（=队列无人响应）发 WeCom 告警（沿用 `notifyVenueUnassigned` 模式），手动兜底用现有 admin 重排工具。
- 不退款取消在 admin 用户/报名详情中可见（`cancellationReason: "揭示后取消（不退款）"`）。

## 7. 分期与验证

| 阶段 | 内容 | Flag | 最小证明 |
|---|---|---|---|
| **Phase 0 — 政策 + 诚实组态** | 揭示后不退款（含条款、取消弹层）；取消真正移除组员 + 通知；塌组接现有顺延退款 | `NO_REFUND_AFTER_REVEAL` | 揭示后取消率、门前 surprise 投诉归零。若不退款已把取消率打到地板，Phase 1 触发频率可能极低——这本身就是胜利 |
| **Phase 1 — 自动回补** | 顺延时刻候补二选一；FCFS 认领；认领扣款入组；队列清空自动退款；WeCom 告警 | `BACKFILL_ENABLED` | 认领率 ≥50%；席位填满率相对 Phase 0 +5pt；候补入座者满意度与原生成员差 <0.3 分 |
| **Phase 2 — 仅数据触发** | 若揭示后取消率仍 >15%：补一个 T-24h 确认触点；若认领率 <30%：有界激励实验（§4.4） | 各自独立 flag | 各自指标 |

**衡量指标（Phase gate）：** 席位填满率（开场实坐/揭示席位）、组完整率（满员开场占比）、候补认领率、候补入座者满意度、**蚕食率护栏**（正价 ¥88 报名转化相对降幅 <5%）、投诉率护栏。

**本地化试点顺序（商业化备忘）：** 上海（last-minute 心智最成熟、¥88 敏感度最低）→ 北京 → 深圳（变动率高，数据价值>收入价值）→ 广州（价格敏感度最高，若认领率仍 ≥50% 则全价决策全国成立）。

## 8. 风险与开放问题

1. **候补无人认领** — 回滚成本为零；降级为只对顺延人群开放（本来就是唯一来源）。
2. **"免费占位刷 lottery"** — 每用户同时最多候补 1 场；认领才扣款天然防刷。
3. **duo 揭示后一人取消** — 留下的伙伴默认单独留下（不强制跟着退）；其退出不退款规则相同。**开放问题：** 是否需要给留下伙伴一个"我也退出"的显式入口？首版不做。
4. **塌组边界（剩 3 人）** — 顺延退款走现有 pipeline，无需新逻辑；文案已覆盖。
5. **不退款的客诉** — 条款 + 取消弹层双重告知；客服话术由运营补（本规格不含）。
6. **法务** — 揭示后不退款属条款变更，上线前需法务确认（含微信审核姿态：退款政策表述须清晰无歧义）。

## 9. 明确不做（Out of Scope）

- 押金/预付机制；处罚阶梯与爽约记录；排桌权重；暂停报名
- 跨池候补迁移、运营定向补位自动化
- 候补折扣（任何百分比）、划线价
- 缩组补偿 credits
- T-24h/T-4h 确认触点（Phase 2 数据触发）
- 已成形组的任何重排/重优化（永远锁定）
- 候补入座者的任何身份标识（无「候补」标签，永远）
