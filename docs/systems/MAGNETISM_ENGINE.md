# 磁场引擎 Magnetism Engine — 品牌命名与 uplift 路线图

> **版本**：2026-08-03 · **状态**：Phase 0 已完成（闭环数据 + 测试锁 + 管理面排雷）· **维护**：匹配域负责人 + PM
> **桥接线**：磁场是看不见的因，同频是遇见时的果，缘分是算不出来的那一部分。

## 1. 命名体系（Canonical）

| 名称 | 英文 | 指称 | 使用层 |
|---|---|---|---|
| **磁场引擎** | Magnetism Engine | 匹配算法系统整体（L1 过滤 → 6D/7D 配对分 → 贪心成组 → 反馈校准） | 内部工程、文档、代码注释 |
| **同频指数** | Resonance Index | 配对分 0-100（内部别名：场强） | 用户侧文案可用 |
| **同频雷达** | Kindred Radar | 用户侧可视化（onboarding 摘要卡） | 已上线，不动 |
| **缘分加成** | Serendipity Bonus | 后置加成族伞名（wouldMeetAgain +5 等） | 内部 + 文案 |
| **引力加成** | Gravity Bonus | 双向 romance +5（引力永远双向 ≡ mutual-only 规则同构） | 内部 + 文案 |
| 热量地图 | Heat Map | 兴趣画像 | 已上线，不动 |

**为什么引擎不叫「同频」**：同赛道竞品 fanju.app 已在市场传播中使用"AI 同频引擎"，独占性不成立；且"同频"只编码同质相吸（homophily）一半的含义，引擎的真实手艺是在相似底子上调配互补差异（背景多样性、原型化学、性别平衡）——磁场同时容纳"同场相吸"与"异极相吸"。

**命名纪律**：
- 用户侧不出现「磁场引擎/算法/权重/评分/数据」等机制词（🔴 文案硬规则）——机制词汇留在工程层。
- 禁用「心动信号」（腾讯恋综《心动的信号》撞名）。
- 「磁力引擎」是快手广告平台（2019-）；英文用 **Magnetism Engine**，不用 Magnetic Engine。
- 对外营销使用前需法务商标核查；当前定位为内部/工程词汇，风险最低。
- 不做代码标识符重命名（`poolMatchingService.ts` 等保持不变）——这是文案与文档层品牌。

悦仔口吻一句话（用户侧讲解用）：「每个人都带着看不见的磁场。悦仔帮你找到磁场对路的人，剩下的嘛——一切看缘分~」

## 2. 设计信条（社交心理学锚点）

| 原则 | 证据 | 引擎落点 |
|---|---|---|
| 同质相吸 Homophily | McPherson, Smith-Lovin & Cook (2001), *Annual Review of Sociology* 27:415-444 | 社交亲和维度（人生阶段/学历/同乡，20%） |
| 相似性-吸引；实际相似性在互动后衰减 | Montoya, Horton & Kirchner (2008), *JSPR* 25(6):889-922（r=.47） | 兴趣热度维度（28%）；引擎只负责开场条件 |
| 结构化渐进自我暴露制造亲密 | Aron et al. (1997), *PSPB* 23(4):363-377 | Social Icebreaker 渐进 phase；Phase 2 对话潜力项 |
| 新颖共同活动 → 自我扩张 | Aron 自我扩张模型 | 尝鲜 intent、缘分机制（Phase 3） |
| 最优独特性：归属 + 差异化的平衡 | Brewer (1991/1996) | 亲和奖励"同"（20%）+ 多样性奖励"异"（15%）；Phase 2 个体粒度化 |
| 算法无法预测面对面化学反应；优化相遇条件 | Finkel et al. (2012), *PSPI* 13(1):3-66 | 化学矩阵是先验占位，Phase 3 用数据校准；组构成优化对话条件 |
| Liking gap：人们低估别人对自己的好感 | Boothby et al. (2018), *Psychological Science* | wouldMeetAgain 信号 + 缘分加成；重聚机制（Phase 3） |

北极星指标：**同频率** = 赛后反馈中 `wouldMeetAgain=true` 或 `hasNewConnections=true` 的参会者占比。

## 3. 评审发现（2026-08-03 全量评审）

架构健康（确定性、服务器所有、flag 门控、单层打分权威），但存在五级严谨性缺口：

1. **学习回路空转**：`match_history` 无写入路径（-1 哨兵 / +5 加成 / 化学校准全读空表）；Thompson bandit 无生产调用方。
2. **冷启动默认值坍缩**：缺数据维度返回常数（70/50），稀疏池分数压成窄带，结果由人工化学矩阵 + 多样性掷硬币主导。
3. **vibeVector 死分支**：化学 30% 权重分支无生产写入者且 key 不匹配。
4. **配置不一致**：阈值三处来源（82/67/52 vs 85/70/55 vs 内联）；`lowCompatibilityThreshold`/`optimalGroupSize` 配而不用；旧 `POST /api/matching/config` 静默不影响线上（管理陷阱）。
5. **Match Compass 粒度幻觉 + 维度数学零单测 + 文档漂移**。

## 4. Uplift 路线图

### Phase 0 — 闭环数据 + 测试锁 + 管理面排雷（S-M，本迭代）

- 派生并回填 `match_history`（从 event_group_outcomes + 组成员两两派生；幂等）；`wouldMeetAgain` 配对语义 = 双方均 true 才 true，一方 false 即 false，否则 null。
- **-1 哨兵由新 flag `MATCH_NEVER_MEET_SENTINEL`（默认关）门控**——写入落地即激活沉睡行为，+5 放通、-1 等政策明确。
- 化学校准聚合器接生产调用（仅积累统计表；校准**读取**路径由 flag `matchChemistryCalibrationEnabled`（默认关）门控，Phase 3 凭影子证据激活）。
- 六个维度 + 组总分的数值单测锁；文档漂移修正。
- vibeVector 死分支删除；加载器死信号清理。
- 旧 config 路由 410 + 阈值读取统一（值不变）。
- **验收**：有 outcome 的组 100% 派生配对行；维度数学测试覆盖；server 测试全绿；管理陷阱移除；flag 默认关时同输入同分（零行为变化证明）。

### 惊艳开局包（2026-08-03，已交付 · flags 默认关 · 待测试池双跑验证后放量）

**策略转向**：干系人决策——不依赖数据做前置条件，纯逻辑 + 社交心理学先验设计，上线即惊艳；数据管道仅后台静默积累用于纠偏。核心认知（Aron 1997 / Finkel 2012）：惊艳感来自相遇设计与"配对层不出错"，不来自配对精度。

已交付（全部 flag 门控，默认关）：

1. **四条组桌规则**（`magnetismGroupRulesEnabled`，`poolMatchingService.ts` 成组门/扩员排序；R1–R3 于成组提交门 + §4.5 三个 redistribution 阶段全部复检，2026-08-03 修复）：
   - R1 无孤立者：组内每人至少 1 个配对分 ≥60（归属感保险；Baumeister & Leary + 峰终定律）
   - R2 能量编排：每组 ≥1 名能量 ≥75 成员；全池无 energizer 时豁免（冷场死局预防；群体动力学启动者结构）
   - R3 话题锚点：全员共享宏观品类，或 ≥⌈n/2⌉ 共享具体话题；任一成员无兴趣数据时跳过（开场不冷场 + 冷启动安全；McPherson 相似地板）
   - R4 新奇分散：第二名 explore 意图候选排序分 −8（仅影响排序，非禁令；Aron 自我扩张）
2. **权重 profile v2**（`magnetismWeightProfileV2Enabled`）：6D = 化学 20 / 兴趣 32 / 亲和 23 / 多样性 15 / 偏好 5 / 语言 5；7D = 19/30/21/14/5/5+6。化学（人工先验，Finkel 2012）降权，兴趣+亲和（Montoya 2008 / McPherson 2001，证据链最强）升权。v1 仍为默认；customWeights/strictness 覆盖优先级不变；缓存 key 加 `|v2` 段。
3. **感知相似性解释层**（无 flag，纯增量）：确定性「共同点」子弹（共享必聊项/共享意图/同乡），LLM prompt + `MatchExplanation.sharedHighlights` 契约 + 小程序 UnifiedRevealCard 渲染；prompt v3 + cache schema v3。Montoya 2008：感知相似性 > 实际相似性。
4. **破冰 phase 曲线审计**：三档静态计划过渐进暴露 + 面子保护清单；修复 group_mirror 元数据错标（warmup→falling）导致的编译器错排 bug；7 项匿名性/归属隐患进 backlog（`docs/icebreaker/icebreaker-system.md` §8）。

**放行条件**：合成池双跑（rules on/off）成组率回退 ≤15% 且规则 100% 合规 → staging 测试池全流程验证 → 翻 flag。原 Phase 1-3 相应转为"验证与纠偏"角色（数据不再是能力解锁前提）。

### Phase 1 — 冷启动诚实打分（M）

- 缺数据维度按对重归一（退出加权后 rescale 至 ∑=1），不再注入常数；兴趣维度有数据时必须产生方差。
- 阈值取值统一为一处配置；消费或删除 `lowCompatibilityThreshold`/`optimalGroupSize`。
- 影子回放升级：从"重排已成型组"到"同候选集重跑成组"，落 `matching_shadow_experiments`——此后一切行为变更的晋升门。
- 评估语义维度启用（仅在此之后安全）。
- **验收**：稀疏池 pair 分数标准差显著高于基线；≥10 池影子回放无成组率/未匹配率回退。
- 原理：Montoya 2008——相似性只在有变异时预测吸引；常数维度是戴着 28% 权重的噪声。

### Phase 2 — 个体严格度 + 对话潜力（L）

- Match Compass 个体粒度：dealbreaker 按每对用户自身严格度判定，权重偏移不再池级平均；接线或移除 4 个未消费偏好字段。
- 成组门加对话潜力项（能量平衡 + 破冰有用度评分积累），flag 门控。
- 解释层 v1：用"同频"语言讲引擎在优化什么（品牌时刻；只讲已上线机制——文案承诺即信任锁定）。
- **验收**：严格度 100 用户的组化学分更高、严格度 0 用户的组多样性更高（≥20 池影子对比）；解释文案过 🔴 规则。
- 原理：Brewer 最优独特性（个体粒度）+ Finkel 2012（优化相遇条件）+ Aron 1997（暴露节奏信号）。

### Phase 3 — 经验化学矩阵 + 缘分机制（M，数据成熟度门）

- 化学矩阵先验 + 收缩校准（`empirical = (n·observed + k·prior)/(n+k)`，保留 ±2 delta 上限与 30 样本地板，按对激活）。
- 缘分机制：wouldMeetAgain 再配对加成接真实数据 + 足迹"重聚"浮现；-1 哨兵按既定政策激活。
- 删除 Thompson bandit（无反事实日志，样本量下影子回放 + 人工校准更可审计）。
- **验收**：≥30 样本原型对全部启用校准；回访用户池同频率 ≥ 基线（目标相对 +10%）；回滚 = 一个 flag。
- 原理：自我扩张 + 闭合 liking gap；矩阵用数据挣回它的 28%。

## 5. 风险注册表

- **隐藏激活**：Phase 0 数据写入即放通 +5（预期）与 -1（flag 挡住）——派生作业当发布对待：先 flag 后回填。
- **高危/不可逆项**（阈值统一、个体严格度、化学校准、-1 哨兵）：一律 flag 门控 → 影子回放证据 → 运营审批门（`matchingOperatorReviewEnabled`）→ 晋升，回滚路径保留一个版本。
- **信任不可逆**：解释层对用户承诺引擎优化 X 之后，改 X 是信任事件——文案只讲已上线行为。
- **度量方法**：池太小不做用户级 A/B；用影子回放 + 池级 switchback，不做池内分流。

## 6. 度量计划

- 主指标：同频率（分新客/回访）；领先指标：atmosphereScore 均值、connectionRadar.overallFit、破冰有用率、**反馈提交率**（低于 ~30% 校准则断粮，Phase 3 顺延）。
- 引擎健康：稀疏池分数方差、成组率、未匹配率、运营改派率、校准样本覆盖。
- 护栏：投诉率、放鸽子率、退款率、30 日再报名率。
