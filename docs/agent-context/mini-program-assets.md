- **WeChat `@3x` image pitfall (2026-06-05 / resolved 2026-06-22):** If a `<Image>` `src` already contains `@3x`, WeChat's runtime can attempt to load `...@3x@3x.webp`, causing 404 / missing image. The fix is to ship a single high-resolution bare `.webp` filename (no `@2x`/`@3x` suffix) for every bundled icon and let WeChat scale it. `validate:icon-transparency` enforces this by failing the build if any `src/assets/icons/**/*.webp` contains `@`.

- **CDN 404 caching incident + fix (2026-08-01):** thumb-v2 files were regenerated with new content hashes on 2026-08-01 (12 archetypes × 4 slots = 48 files) but the last CDN upload predated them (Jul 31 17:00 server mtime), so only devices that happened to request a new-hash URL hit 404s — the `avatar_asset_error` seen by some testers. **Why it persisted per-device:** nginx `/static/` used `add_header Cache-Control "public, max-age=31536000, immutable" always`; the `always` flag also applied to **error responses**, so a cached 404 blocked retries for up to a year even after files were uploaded. **Fix (deployed 2026-08-01):** `/etc/nginx/conf.d/joyjoin.conf` `/static/` block now has `error_page 404 = @static404;` and the named `location @static404` returns `Cache-Control: no-store, max-age=0` + `return 404`. Verified live: missing path → 404 + `no-store`; existing path → 200 + immutable unchanged. Keep 404s non-cacheable. Devices that cached a pre-fix 404 need a one-time WeChat cache clear. **Operational rule:** after regenerating assets with new hashes (e.g. `build-profile-pixel-v2-assets.mjs`), immediately re-run `npm run upload:cdn-assets -w mini-program` (or the `Upload CDN Assets` workflow) — new-hash references 404 until the next sync.

- **Image aspect-ratio discipline (2026-06-23):** Fixed-height containers paired with `<Image mode='aspectFit'>` create blank bands or cropping when the container aspect does not match the source asset. For images whose rendered size must scale with width, use `mode='widthFix'` and set the container to `height: auto` (or `aspect-ratio: W / H`). When using `aspectFit`, make the container's aspect ratio match the source (e.g., `aspect-ratio: 800 / 531` for `lovart-generic-error.webp`, `aspect-ratio: 1 / 1` for square Lovart empty-state illustrations, `aspect-ratio: 750 / 563` for the Discover promo banner). The pool-registration hero, `StatusCard`, event-detail, pool-group-detail, icebreaker-session, squad-unboxing, and rewards empty states were audited and fixed for this on 2026-06-23.
