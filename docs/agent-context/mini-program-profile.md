**Mini-program Profile V1.7 (2026-07-16; profile-linked migration remains active):**

- The identity stage uses the user's canonical V4 archetype in the Profile-only V2 paper-doll renderer over the existing warm-white/purple UI. The required baseline is 60 reusable WebPs: 12 full-body 512×768 base characters wearing permanent modest underwear, plus 48 cropped transparent starter-equipment layers (four per archetype). **Layer extraction (2026-07-21):** starter layers are derived by atlas character-difference from each archetype's 2×3 dressed-stage `atlas-source.png` (coarse silhouette + head-score alignment, diff-bounds placements, hard fit gate ≤3% missed/≤5% extra) — never from isolated equipment sheets, whose garment poses do not match the body (arm/shoe fit incident). The same equipment layer is both the wardrobe image and the layer anchored onto the body. Character-image failure leaves the permanent-base character fallback visible. Formal Alang art is not used here. Pipeline details: `assets-source/profile-pixel-v2/README.md`; the build replaces only generated subtrees (stage art is preserved).

- **My-Image real WebGL 3D avatar (2026-07-18, garment overhaul 2026-07-18):** The `pages/profile-linked/my-image` stage renders a real WebGL 3D spider persona via `PixelAvatar3D` (`apps/mini-program/src/components/profile/PixelAvatar3D.tsx`) on `three@0.152.2` — pinned because r163+ drops WebGL1; do not upgrade without a WebGL2 audit, and do not adopt `three-platformize` (the custom adapter in `src/lib/profile/avatar3d/avatar3dPlatform.ts` owns WeChat canvas/RAF interop, DPR capped at 1.5). `src/lib/profile/avatar3d/` builds the procedural low-poly spider (`spiderModel.ts`): every body part is an independent `Group`, underwear meshes are permanent, and the four spider starter garments are **pre-built unique meshes registered in `spiderStarterGarments.ts`** (bomber jacket / cargo shorts / high-top sneakers / web+comm accessory, each with named detail meshes locked by `spiderModel.test.ts` + `equipment3dMapping.test.ts`). Dressing/undressing only flips `garment.visible` — meshes are never created, destroyed, or disposed at runtime. **There is no texture path**: garments are solid-palette procedural meshes (colors sampled from the V2 art in `avatar3dPalettes.ts`), so no texture ownership issues exist; `model.dispose()` is the single resource-release point. Only the four spider starter assetKeys resolve to 3D descriptors (`equipment3dMapping.ts`); the other 11 archetypes' starters stay V2-thumbnail-only, and **only `archetypeId === 'spider'` boots WebGL** — every other persona renders the static front-view V2 composite with no steady-state notice (the 5-stop pseudo-3D turntable was removed 2026-08-01: static frames never read as real rotation; the transient 「3D 形象正在准备」 pill was removed the same day — a permanent note would only ask a question the UI can't answer; spider keeps the true WebGL 3D, and genuine device degradation still shows 「当前设备暂不支持 3D 预览，已切换为经典形象」). WebGL boot failures fall back the same way with an explicit `Avatar3DFallbackReason` (unsupported-archetype / canvas-component-missing / canvas-query-missing / canvas-node-missing / webgl-context-missing / session-init-failed / context-lost), reported via the optional `onStatusChange` prop and `logWarn`. QA surface: dev builds (`TARO_APP_AVATAR_3D_QA === 'true'`, a `defineConstant` in `apps/mini-program/config/index.ts`) show a "3D 调试" entry on my-image leading to `pages/profile-linked/my-image/qa3d` (view presets, per-slot toggles, external yaw, live status/reason line). **Chunk routing (2026-07-18):** three.js (~460KB) must never enter the root `vendors.js` (main package) — `apps/mini-program/config/index.ts::miniProgramManualChunks` routes `three`, `src/lib/profile/avatar3d/*`, and `PixelAvatar3D.tsx` into the slash-named chunk `pages/profile-linked/three-avatar`, emitting it inside the profile-linked subpackage (verified: main package deflate est back to 1.91MB baseline, subpackage 624.6 KiB < 1.8MB limit). The function mirrors Taro 4.2 vite-runner's react-branch `getManualChunks()` verbatim (taro/vendors/babelHelpers/common) — re-sync it when upgrading Taro. WeChat forbids main-package → subpackage requires, so **nothing outside `pages/profile-linked/*` may import three, avatar3d, or PixelAvatar3D**; check with `grep -l "three-avatar" dist/*.js` (must be empty) after any new importer.
- **My-Image stage scene + subpackage style guard (2026-07-21):** The my-image stage wraps `PixelAvatar3D` in `IdentityStageScene` (`layerImageMode='aspectFill'` — the wide street art crops undistorted into the near-square stage; total art failure degrades to children over the legacy grid backdrop). **Subpackage WXSS splitting is a hard trap**: WeChat applies only the page's own WXSS + the `app.wxss` chain (`app.wxss` → `common.wxss`), and Taro's chunk graph can move a component's rules into an unreachable chunk (the V2 composite rules were chunked into `pages/profile-linked/three-avatar.wxss`, blanking the stage for all 11 non-spider archetypes). Any component SCSS used by a `profile-linked` page MUST be `@use`d in the page SCSS (see the header comment of `pages/profile-linked/my-image/index.scss`); `npm run verify:subpackage-styles -w mini-program` asserts the required selectors in compiled page WXSS and runs in `taro-weapp-build.yml` after `check:package-size`. **Slot hotspots** (open-source slot hit-rect pattern): `PixelAvatarComposite` accepts `slotHotspots` + `onSlotTap` — placement-rect hit areas on the character; tapping the jacket/shoes on the character jumps to that wardrobe slot. Wardrobe slot tabs show an equipped-state dot; equipment layers fade in on item change (240ms opacity, RM-suppressed). The CDN manifest now carries `v2/stage/*.webp` so the production scene can load (upload via the CDN workflow).
- **Percentage-height stage trap (2026-07-23):** `IdentityStageScene` sizes itself with `height: 100%`, which never resolves against a host that only declares `min-height` — the scene collapses to 0 height and its `overflow: hidden` blanks the entire identity card (the Profile-tab blank-card bug). Stage hosts MUST set an explicit `height` next to `min-height` (pattern: `my-image__stage`); the component also carries `min-height: inherit` as component-level defense. The `verify:subpackage-styles` gate asserts both.
- **Equipment thumbnails (2026-07-29; garment-only overhaul 2026-08-01):** every equipment item ships a dedicated square `thumb-v2` (256×256) alongside its `layer-v2`. Thumbs are clean garment-only product shots derived from the isolated garment cells (2×2 `equipment-sheet-source.png` for the nine dressed-stage archetypes; isolated atlas cells for cat/elephant/turtle), chroma-keyed, tight-cropped, lanczos-downscaled into a 224px art window with 16px padding; the worn-layer crops are no longer used because their seam body pixels (chin fur, belly, leg strands) read as dirty scribble in small tiles. `getPixelEquipmentThumbnailUrl` returns the thumbnail (fallback: layer URL); my-image inventory/shop/recent and profile slot art all render thumbnails.
