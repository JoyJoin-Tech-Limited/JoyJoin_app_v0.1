# Social Icebreaker — Agent Context

> Extracted from AGENTS.md §6 (2026-07-31). Load when building, debugging, or extending the social icebreaker session flow. Skill: `social-icebreaker-domain`. Canonical doc: `docs/icebreaker/icebreaker-system.md`.

**Social Icebreaker:** Primary in-event flow is `/icebreaker/:sessionId` → Social Icebreaker. `/icebreaker-game` (AI Card Game) is optional deep-dive, not default. **`/start` failure diagnostics (2026-07-11):** access denial returns a structured `code` (`GROUP_EXPIRED`/`NOT_MEMBER_OF_GROUP`/`SESSION_NOT_FOUND` + event analogues) and logs `[SocialIcebreaker] /start access denied`; the mini-program tier selector writes `tier-selector:start-session-failed` to the WeChat realtime log with a scenario toast instead of the silent `创建没成功，再试试`.
- **Custom mode (`custom` tier):** host-driven free-form flow. Server enters `phase_selection` between phases; host picks next phase via `POST .../select-phase` and can end early via `POST .../end-session`. Feature flag: `SOCIAL_ICEBREAKER_CUSTOM_MODE_ENABLED` (default `true`). In-flight custom sessions continue if the flag is disabled. **Phase-selection data is host-only (2026-07-31):** `sanitizeStateForClient` strips `phaseSelectionId` for non-host callers and `buildClientState` attaches `selectablePhases` only to the host — players never receive the actionable nonce or picker list. CustomModeSection renders phase emblems via `JoyJoinIcon` (`tier='phase'`), never raw emoji. Route-level locks: `socialIcebreakerCustomRoutes.test.ts` (16 tests).
- Server routes are split across `socialIcebreaker.ts` (start/session), `socialIcebreakerGameplayCore.ts` (micro-challenge, lie-detective, personality-dice), `socialIcebreakerGameplayExtra.ts` (quip-battle, undercover-word, group-mirror, speed-friending, moment-card), `socialIcebreakerCustom.ts`, `socialIcebreakerTier.ts`, and `socialIcebreakerExtended.ts`. AI generation modules are split under `apps/server/src/socialIcebreaker*AI.ts` with a shared `socialIcebreakerAICore.ts`.
- **Moment Card server render:** `GET /api/social-icebreaker/:id/moment-card.png` (feature-flagged: `SOCIAL_ICEBREAKER_ENABLE_MOMENT_CARD_SERVER_RENDER`)
- **Bonus gate:** when `mini_script` is next eligible, advance pauses at `bonusGateOffered` for host+player vote (`POST /api/miniscript/bonus/respond`, `POST /api/miniscript/bonus/sentiment`). The full mini-script phase surface (`generate`/`assign-roles`/`reveal-act`/`vote`/`reveal-solution`/`ready` + both bonus routes) lives at **top-level `/api/miniscript/*`** with `socialSessionId` in the body — never under `/api/social-icebreaker/:id/...` (canonical since 2026-08-06; client enforced by `miniscriptClientPathContract.test.ts`)
- **Phase metrics:** `social_icebreaker_phase_metrics` table tracks `dwellTimeMs` per phase on every advance

**Icebreaker tiers & vibe:** Host selects time budget + vibe. Budgets: `breeze` (破冰局, 40min) / `glow` (畅聊局, 60min) / `blaze` (狂欢局, 90min). Vibe: `深聊` (deep_chat, connection-first) / `均衡` (balanced, standard mix) / `暢玩` (play_fun, energy-first). The mini-program tier selector (`pages/icebreaker-session/tier-selector`) renders 3 human-intention preset cards (`轻松破冰` = breeze+balanced, `深度畅聊` = glow+deep_chat · recommended, `游戏狂欢` = blaze+play_fun); an "自定义时长 / 氛围" toggle reveals the original 3×3 grid for power users. Custom mode (`自由局`) remains as a separate card. Preset/custom card backgrounds are CDN-backed Lovart WebP art, with local bundled fallbacks. Template compiler (`resolveTemplateSlots` in `packages/shared/src/runPlanCompiler.ts`) resolves phase selection + durations per vibe×tier combo. Feature-flagged: `RUN_PLAN_TEMPLATES_ENABLED`. See `docs/icebreaker/icebreaker-system.md`.

**In-session UI (2026-07-16):** A slim host band replaces the permanent XiaoyueChatBubble card across all 10 phases. It shows a 40rpx expression avatar + a single toneLine (clamp 2 lines), with no background/border. The full mascot bubble is event-driven: it appears only at emotional peaks (everyone-ready celebration, recap). Host tools are consolidated in a `⋯` menu (outlined-circle trigger, all phases where valid actions exist; tier-change only in waiting/warmup). During `warmup`, the old `当前·深度畅聊·60min` chip is removed; the current mode is shown as a plain caption under the welcome band, and the only change entry is the `⋯` menu. A one-time coachmark points hosts to the menu on first entry. Warmup is a zero-scroll 4-band layout: welcome band, hero card slot (flex:1), chrome-less presence strip, and a single white action bar. The hero card is a state machine: host picks the mood inside the same card, the card shows a generating shimmer, then deal-flips to the first topic (the only wow moment). `深聊` prompts collapse into a `深聊锦囊 ›` expander (first card auto-teaches by expanding once). Ready CTA morphs from `我准备好了` to a calm `已准备 ✓` state with a small `取消` link; host sees `进入下一题 ›` or `本轮结束` depending on card position. AIGC labels are consolidated into a quiet single-line footer. Sync state is calm-by-default: no indicator while healthy, grey dot + toast only on poll failure. Reduced-motion degrades all animations to 150ms opacity crossfade.

**Game Design Agent:** Compiles dynamic run plan per session using 70% rule engine + 30% LLM. Reads archetype mix + behavioral signals (mood, commonGround, completion rate, pulse). Rule engine runs on every compilation (deterministic); LLM enhances selection + ordering with 3s timeout fallback. See `docs/icebreaker/icebreaker-system.md` §5.

**Topics 502 resilience round (2026-07-28, root-caused from a device recording stuck 11s+ on 「悦仔正在出题…」):** The `/topics` route itself can never emit a 5xx (6s LLM race → curated-topic fallback; save failure still returns playable topics), so a 502 means the request never reached a healthy route (gateway/dev-server restart) — transient infra, and the client now rides through it instead of dying. `TOPICS_REQUEST_TIMEOUT_MS` dropped 12s→8s (>8s is infra territory where retrying beats waiting). `performSocialAction` accepts `onError`; `classifyTopicsFailure` (5xx or bare network/timeout → `server`; 4xx → `generic`) routes transient failures into a patient backoff ladder (2s/5s/10s, ≤3 attempts, `TOPICS_SERVER_RETRY_MAX`) with a visible `recovering` hero-card state (`topicsRecovery` prop → 「网络打了个盹，悦仔正在重新连接…（自动重试 N/3）」) — 4xx still goes straight to the terminal error card. The backoff timer is phase-guarded via `phaseRef` so a fuse-advanced session never regenerates topics outside warmup. Generating copy is staged (「悦仔正在出题…」 → 「还在思考中，马上就好~」 at 4s). Regression tests in `warmupAndPhaseLogic.test.ts` (`getWarmupCardState` recovering priority, `classifyTopicsFailure`, `getTopicsServerRetryDelayMs`).

**Event feedback write path id-family canonicalization (2026-08-07, root-caused from the single-test 局 FK 500):** `POST /api/events/:eventId/feedback` used to insert the raw `:eventId` straight into `event_feedback.event_id` — but the mini-program always arrives with a **non-`events` id** after squad-unboxing: `useSquadUnboxingController` redirects to `event-detail?id=${blindBoxEventId}`, and event-detail passes `event.id` through to feedback. Inserting a `blind_box_events.id` (or `event_pools.id`) into a column FK'd to `events.id` throws `event_feedback_event_id_events_id_fk` → 500 "Failed to create feedback" (first reproduced on the 单人调试局 flow; every real matched group would hit the same path once it exists). The route now resolves the canonical `events.id` via `resolveCanonicalEventId` (`apps/server/src/lib/resolveCanonicalEventId.ts`) — three families: direct `events.id`, `blind_box_events.id` via `event_pool_groups.blindBoxEventId → eventId` back-link, and `event_pools.id` via the viewer's registration `assignedGroupId → group.eventId`; unresolvable ids 404. All downstream writes (`storage.createEventFeedback`, `upsertConnection`, mutual-match notifications, shadow recommendation) use the canonical id. **Any new route that writes an FK referencing `events.id` must canonicalize first** — reuse `resolveCanonicalEventId`, don't trust `:eventId` to be an `events` id. Regression locks: `resolveCanonicalEventId.test.ts` (4 families incl. unresolvable) + `contentSafetyFeedbackRoute.test.ts` (db mock now resolves the probe).
