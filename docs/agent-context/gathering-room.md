# Gathering Room (集结房间) — Agent Context

> Added 2026-08-09. Load when working on `pages/gathering-room`, room presence, or the avatar scene. PRD: `docs/product/gathering-room-prd.md`. Equipment/avatar system: `docs/agent-context/mini-program-assets.md`.

**Purpose:** the online pre-event anteroom for one matched pool group — 4–6 members see their existing V2 pixel avatars (with equipped outfits) around a table in the days between match success and the offline event. Not a chat room, not a game lobby; the room's lifecycle is driven entirely by the real event's state machine. Core promise: 把焦虑的等待，变成期待的等待.

**Client surface (2026-08-07):**
- Page `pages/gathering-room/index` in its own subpackage (root constant `MINI_PROGRAM_GATHERING_ROOM_SUBPACKAGE_ROOT` in `lib/onboarding/onboardingRoutes.ts`). View-model: `useGatheringRoomController.ts`; scene: `components/gathering-room/GatheringRoomScene.tsx` (+ SCSS). Page WXSS carries 5 required selectors verified by `scripts/verify-subpackage-styles.mjs` after `build:weapp`.
- Entries (both flag-gated on `gatheringRoomEnabled`): pool-group-detail primary CTA (`openGatheringRoom`; 开始破冰 demoted to secondary) and squad-unboxing post-confirm-attendance redirect (`replaceWithGatheringRoom`; flag off → redirect logic byte-identical to before).

**Flags:** `gatheringRoomEnabled` (env `GATHERING_ROOM_ENABLED`, default `false` — ships dark until staging/真机验证通过) gates entry CTAs and the page. The room renders existing V2 `PixelAvatarComposite` avatars with each member's current equipment. `ROOM_ART_READY` is a compile-time constant in `GatheringRoomScene.tsx` (`true`): the scene renders the delivered composite room-art WebP (`room-composite-v1.webp`) with CSS placeholder fallback when `false`. Seat anchors and the character layer remain stable across art swaps.

**REST contract:** `GET /api/pool-groups/:groupId/room-state` (`requireAuth`, `routes/domains/userEventPools.ts`; 403 non-member, 404 unknown group) → `GatheringRoomStateResponse` (`packages/shared/src/api/gatheringRoom.ts`): `{ groupId, blindBoxEventId | null, totalParticipants, confirmedCount, eventDateTime | null, members[] }`. Member DTO carries `attendanceStatus` (`pending | confirmed | late | absent`), `topInterests`, visibility-gated `ageLabel` / `industryNicheLabel`, and the existing avatar-system `outfit` + `equippedItems` (resolved from `equipmentRepository.getEquipmentLooksForUsers`). `blindBoxEventId` is the WS room id; it is **null** when the blind-box event row has not been created yet — clients must skip the WS join in that case. `eventDateTime` drives the live header countdown.

**WS presence (`wsService.ts`, types in `packages/shared/src/wsEvents.ts`):** client joins with `USER_JOINED { userId, eventId: blindBoxEventId }`. Server replies to the joining socket with `ROOM_PRESENCE_STATE` (full snapshot) and broadcasts `ROOM_MEMBER_ENTERED` / `ROOM_MEMBER_LEFT` to the room. Leave handling: 5 s grace (`ROOM_LEAVE_GRACE_MS`) before `ROOM_MEMBER_LEFT` fires — rejoin inside the window cancels it silently (flap tolerance; mini-programs disconnect on background); a multi-socket user stays present until the last socket leaves. `ROOM_POKE` is relayed only from present senders, emoji whitelisted to `ROOM_POKE_EMOJIS` (`wave`/`hi-five`/`drink`), throttled to one per sender per 2 s (`ROOM_POKE_MIN_INTERVAL_MS`); validation/throttle failures are silently dropped. `USER_CONFIRMED` (existing confirm-attendance broadcast) drives the all-confirmed celebration.

**Presence three-state model (PRD §3):** per member — confirmed/late attendance → **seated** (persistent); else in the WS presence set → **在场**; else **未现身** (name-card placeholder, narratively "正在路上"). Source of truth split: **attendance is persistent and DB-backed** (`event_attendance` via `attendanceRepo.getAttendanceStatuses` — a confirmed member absent from `matchedAttendees` still reports `confirmed`; members with no row default to `pending`); **presence is ephemeral**, lives only in the WS layer, and is never persisted.

**Analytics:** `POST /api/analytics/gathering-room` (`routes/domains/analytics.ts`, `discoverAnalyticsLimiter`; write failures non-fatal). Whitelist: `room_entered`, `room_poke`, `room_confirm_attendance`, `room_all_present` — canonical list `GATHERING_ROOM_ANALYTICS_EVENT_TYPES` in `packages/shared/src/api/gatheringRoom.ts`, mirrored server-side; keep both in sync. Client helper: `lib/analytics/gatheringRoomAnalytics.ts`.

**Tests:** `apps/server/src/__tests__/gatheringRoomState.test.ts`, `gatheringRoomPresence.test.ts` (grace/flap/multi-socket/poke throttle), `gatheringRoomAnalyticsRoutes.test.ts` — run via `npm run test -w @joyjoin/server -- gatheringRoom`.

**Freeze fix + copy correctness round (2026-08-12):**
- **Rules-of-hooks crash (卡死 root-cause):** the page had 4 early returns BEFORE 3 hook calls — when room data loaded and the room first rendered, the hook count changed mid-render and React crashed, freezing the last committed frame (the loading screen) forever. Fix: all hooks run unconditionally above every early return (committed in `1120965d4`). When touching this page, never place a hook below an early return; `react-hooks/rules-of-hooks` catches this locally but is NOT yet part of the CI gate (recorded candidate improvement).
- **`周六见` copy was a factual lie** for any non-Saturday event: confirm-button, celebration text, and toast all hardcoded it. Now derived via `formatMeetDayLabel(eventDateTime)` (exported from `useGatheringRoomController.ts`, `WEEKDAY_LABELS` convention, falls back to neutral `活动见` when the date is missing/unparseable).
- **Empty-members room state:** the scene wrapper now renders a centered `gathering-room__scene-empty` surface (「同桌还在路上」) instead of bare art when `memberProfiles.length === 0`.
- **Sheet-mask close** now fires `haptics('light')` (`closeSheet` in the controller covers both the mask and the 返回 button).
