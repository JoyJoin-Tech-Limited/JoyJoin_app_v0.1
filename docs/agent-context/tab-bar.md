# Custom Tab Bar — Agent Context

> Extracted from AGENTS.md §6 (2026-07-31). Load when modifying `native-custom-tab-bar` or tab routing.

**Custom tab bar geometry (2026-06-04 / visual polish 2026-06-05 / hardened 2026-06-11 / simplified 2026-06-23 / center-ring re-anchored 2026-07-16):**
- Surface height: `$tab-bar-height: 128rpx`; root footprint: `$tab-bar-root-height: 182rpx`. **Center ring vertical anchor (2026-07-16):** `.joy-custom-tab-bar__center-wrap` is `top: -44rpx` so the 164rpx ring's **center sits exactly on the surface's top edge** (82rpx above the bar, bottom half resting inside the bar; top 44rpx overflows the 182rpx root upward — root has no overflow clipping). The center label lives in the free band below the ring via `margin-top: 8rpx` (was `-28rpx`, which tucked it behind the opaque ring and hid it). Derivation comment lives in `index.wxss` — off the 8rpx grid by derivation, do NOT round.
- Center CTA button is a **root sibling** of `.joy-custom-tab-bar__surface` (not nested inside) to avoid surface clipping. It uses `solid #FFF4F8` fill (`$color-bg-tint-pink`) — the previous `#8B5CF6` clashed with the multi-color JoyJoin logo. Gradient was purged from all mini-program CTAs
- **Center positioning uses a flexbox wrapper** (`.joy-custom-tab-bar__center-wrap` with `justify-content: center`) instead of the fragile `left: 50%; transform: translateX(-50%)` pattern. The `transform` approach is unsafe in the WeChat mini-program renderer because `setData` re-renders can drop the `translateX(-50%)` offset when combined with `hover-class` transforms, causing the button to shift right by ~half its width
- Center outer ring: `2rpx solid rgba(255, 107, 157, 0.18)` (`$color-secondary` at ~18% opacity) for subtle definition without competing with the logo
- Surface layering: double shadow (`0 -4rpx 24rpx rgba(45,49,66,0.06), 0 8rpx 16rpx rgba(45,49,66,0.12)`) plus `1rpx solid rgba(139, 92, 246, 0.06)` top border (`$color-primary` at 6% opacity) for soft lift off the page. The lower shadow's offset (8rpx) + half-blur (8rpx) stays inside the 16rpx surface-to-screen gap, so it reads as floating on Android too — where `env(safe-area-inset-bottom)` is 0 — instead of being clipped at the screen edge
- Center button width reduced to `148rpx` (was `192rpx`) to prevent overlapping adjacent tabs on narrow screens
- Selected tab label uses `$color-primary-dark` (`#7C3AED`, 5.70:1 on white / 5.17:1 on the 10% active pill) at weight 600; inactive label is `$color-text-secondary-on-light` (`#59616C`, 6.27:1) — both replaced the earlier `#8B5CF6` (4.23:1) and `#9CA3AF` (2.54:1), which failed the 4.5:1 small-text floor. The icon swaps to its vivid `*_icon.png` variant via stacked opacity
- Active tab pill: the 64rpx icon wrap hugging the icon carries `rgba(139, 92, 246, 0.10)` + `border-radius: 24rpx` (state paint, no transition). The item itself has no background — the old full-item tile measured 115.5×112rpx around a 48rpx icon
- Haptics: `wx.vibrateShort({ type: 'light' })` on every side-tab tap
- State sync: 50ms debounce + shallow diff in native `syncState`; badge updates use WeChat path syntax (`leftTabs[idx].badgeCount`) to avoid array reconstruction and icon flicker. `syncState` is skipped while offline and replayed on reconnect via `wx.onNetworkStatusChange`
- **Route-truth selection (2026-11-17):** `selected` has one **route-derived** writer — the visible page's `useCustomTabBarSync`, which publishes its own `page.route` index on every `useDidShow` (NOT gated by `enabled`), records it in `tabBarState.setTabBarSelected` (a recorded projection for diagnostics/tests; nothing in production reads it back yet), and retries the native push on `0/16/64/160/400ms` while `page.getTabBar()` is still undefined, aborting the attempt if the current page instance changed. Tap paths additionally write an optimistic `selected` (and `_reconcileSelection` / fail rollback write it), so "one writer" means one *route-derived* writer, not one assignment in the file. The native component runs `_reconcileSelection()` in `attached` (seeding selection + visibility as the instance mounts, so a fresh instance normally paints already lit) and again in `pageLifetimes.show` as a backstop for swipe-back/deep-link/re-attach; `show` defers to a push that landed within `PUSH_SETTLE_MS = 400`. **Neither of those reads can be trusted alone (2026-11-22):** WeChat's documented creation order is *component attached → component `pageLifetimes.show` → Page.onLoad → Page.onShow*, and a hidden tab page is kept as a **dangling page outside the page stack**. So both reads run **before** the incoming page exists in the stack and report the tab the user is **leaving** (a 连接→足迹 switch paints 连接), and both fire exactly once at the start of the transition — the earlier claim that this is "one frame, corrected by the page's own publish" was wrong: the publish is a bounded retry chain (0/16/64/160/400 ms) that can miss (late `getTabBar()`, or the platform resolving the outgoing page's instance), and once it misses nothing re-read the route again, so the wrong highlight persisted until the tab was left and re-entered. `attached`/`show` now also arm **one** deferred re-read (`ROUTE_RECHECK_MS = 400`, `_armRouteRecheck`), which converges on the settled stack; a route push (`setSelected`), a tab tap (`_switchToIndex`), `pageLifetimes.hide`, and `detached` all disarm it, and a push that lands while it is pending supersedes it (arm-time `_lastPushAt` token). Historical defect this closes: the one-shot push could be lost, leaving the bar lit only on the user's **second** tap of that tab (reported on 足迹 because it is usually the first non-start tab a session visits).
- **Latest-intent routing (2026-11-09, pending-drop added 2026-11-17):** at most one native `wx.switchTab` is active and only the newest pending destination is retained. Settling the active request dispatches that pending intent, so a rapid A→B→C sequence can never leave B selected after C. A pending destination whose index already equals the visible route is dropped instead of re-issued.
- Failure rollback applies only to the latest request: selection returns to the visible route (or the prior selection only when no route is available) and shows `切换失败，请重试`. Stale success/failure callbacks cannot overwrite the newer destination or show a stale toast. Analytics events `mini_program_tab_bar_switch_fail` and `mini_program_center_button_switch_fail` include stale status
- **Bounded callback wait:** if the runtime invokes neither callback, a 400ms watchdog releases the active request. It dispatches the newest pending destination; with no pending destination it restores the visible-route highlight. The watchdog expires only the platform wait, not native navigation itself
- Active highlight: per-item `.joy-custom-tab-bar__item--active` background (`rgba(139, 92, 246, 0.08)` + `border-radius: 20rpx`) replaces the previous sliding translateX pill. The orphaned sliding-pill geometry, CSS, and `pillTranslateX`/`pillWidth`/`pillTransitionEnabled` data fields were removed 2026-06-23. Hardcoded `selected === 4` checks were replaced with the `CENTER_TAB_INDEX` constant
- Lifecycle hygiene: `attached` registers `wx.getNetworkType` and `wx.onNetworkStatusChange`; `detached` clears `_syncTimer`, `_switchTimer`, `_announcementTimer`, invalidates outstanding callbacks, drops pending intent, and unregisters the network listener. `pageLifetimes.show` restores route-truth selection on swipe-back
- Motion (2026-11-17): the active highlight is a **state paint, never a transition** — a `switchTab` reveals a fresh instance that is already correct, so an animated highlight only ever encoded a wrong-direction correction. Icon selection is a `src` swap on a single `<image>` (since 2026-11-22; the dual-icon opacity toggle never painted on device), with no crossfade. Press feedback is 0ms `hover-start-time` / 100ms `hover-stay-time` on the icon wrap only (`scale(.94)` + `opacity:.72`), so the label no longer drags or dims. The center label's colour transition and the center button's box-shadow transition were removed; the center badge's infinite `pulse-dot` was removed. Two animations intentionally remain and are NOT selection state: `badge-pop-in` (a badge appearing) and the center outer ring's 150ms `background-color`/`border-color` tint. `logo-settle` plays once per app session (module flag `hasPlayedLogoEntrance`), not on every tab page's first visit. Inactive icons carry no extra `opacity` multiplier — `*_inactive.png` is already muted. Press motion is neutralised by both the low-end class and `@media (prefers-reduced-motion: reduce)`
- Low-end gating: `wx.getSystemInfoSync().benchmarkLevel <= 15` **or** an iOS device without a `benchmarkLevel` value disables all animations via `.joy-custom-tab-bar--low-end` class (WXSS overrides). `will-change` hints are reset to `auto` on low-end + reduced-motion to free GPU layers.
- No collapse API (removed 2026-11-19): `setCollapsed` wrote `data.collapsed` and announced `标签栏已收起`, but no WXML expression or WXSS rule ever consumed the field, so the bar never moved and the announcement was false. Discover's scroll handler + `tab_bar_collapsed`/`tab_bar_expanded` analytics were removed with it. Do not reintroduce a collapse lever without a rendered consumer
- Screen-reader announcements: tab-switch success writes `data.announcement` (e.g., `已切换到足迹`) and clears after 1s
- Visibility state: `data.hidden` defaults to `true`; `_reconcileSelection()` is the only route-derived writer — it reveals and lights the bar at `attached` on a tab route, hides it on a known non-tab route, and leaves it untouched when the page stack is empty/unreadable (the page hook covers that window). `setSelected()` also reveals, but only from the page hook or a tap. The WXML root must consume `hidden` (`wx:if="{{!hidden && !sheetOpen}}"`)—a data-only hide flag does not remove the native bar
- **`catch-move` pitfall (2026-06-11):** Do NOT add `catch-move` to the tab bar root. In WeChat's native `cover-view` layer, `catch-move` on a parent intercepts `touchmove` events and blocks the tap gesture recognizer for child elements — causes all tab buttons to become unresponsive. The tab bar is `position: fixed` and does not need scroll blocking.
- **Tab bar WXML pitfall (2026-06-15):** The active native custom tab bar intentionally uses plain `<view>`/`<image>` (not `<cover-view>`/`<cover-image>`). WeChat's `cover-view` overlay only reliably renders `cover-view`/`cover-image` children; a hybrid tree where `<cover-view>` wraps `<view>`/`<image>` children causes blank tab icons and labels. Keep the root, surface, tabs, and center button as `<view>`/`<image>`.
- **Tab bar visibility smoke test (2026-06-18, reveal contract updated 2026-11-17):** After any tab-bar or routing change, verify with WeChat DevTools that the tab bar is actually visible on tab pages (computed `display: block`, no `hidden` attribute) and hidden on non-tab pages. The WXML tree alone is not enough — the component can be present while `hidden=""` makes it `display: none`. `_reconcileSelection()` normalizes route formats (`pages/discover/index`, `/pages/discover/index`, and Taro timestamp queries) and is the only route-derived writer: it reveals + lights the bar at `attached` on an allow-listed route, hides it on a known non-tab route, and leaves it untouched when the page stack is unreadable. The page hook's `setSelected()` is the freshness signal that `pageLifetimes.show` defers to. See `docs/runbooks/mini-program-tab-bar-smoke.md` for the canonical procedure and `apps/mini-program/src/native-custom-tab-bar/__tests__/tabBarBehavior.test.ts` for regression tests.
- **CSS custom properties:** 8 brand tokens (`--jj-primary`, `--jj-secondary`, `--jj-bg-tint-pink`, etc.) declared on `.joy-custom-tab-bar`. All hardcoded hex values in WXSS now reference these variables for maintainability. New colors must use this pattern.
- Active pill `border-radius`: `24rpx` (on 8rpx grid; was `20rpx` before 2026-06-11 fix).
- Haptics: platform-aware — `type: 'light'` on iOS, plain `wx.vibrateShort()` on Android. Silently fails on unsupported devices
- 8rpx rhythm: all spacing normalized to the grid (no 6rpx, 12rpx, or negative-2rpx values)
- **setSelected no-op guard (2026-07-24):** `setSelected` skips `setData` when the tab is already selected and the bar is already visible, preventing unnecessary re-renders on redundant tab taps.
- **Single-icon `src` swap (2026-11-22):** Each tab mounts ONE `<image>` whose `src` is `selected === item.index ? item.selectedIcon : item.icon`. This replaced the 2026-07-24 dual-icon opacity crossfade, whose stacked absolutely-positioned overlay never painted on real devices — the selected tab kept showing the muted artwork while its label already read as active. Selection is also re-read from the route ~400ms after every show/push, so a mid-transition push can no longer leave a tab stuck unlit until a second tap.
