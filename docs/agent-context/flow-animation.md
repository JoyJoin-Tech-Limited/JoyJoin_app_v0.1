# Flow-Animation Overlays — Agent Context

> Created 2026-07-31. Load when working on the once-per-user flow-animation overlays (Flow 1 `joyjoin-intro` at profile-review, Flow 2 `blind-box-lifecycle` after first pool registration). Skills: `joyjoin-brand-guidelines`, `wow-elements` (motion craft), `feature-flags-launch-config` (kill gates).

**Two once-per-user overlays (2026-07-31 uplift):** Flow 1 `joyjoin-intro` mounts in `pages/onboarding/profile-review/index.tsx` (shown once at profile-review completion, before routing to nextStep). Flow 2 `blind-box-lifecycle` mounts in `pages/pool-registration/index.tsx` (shown once after the first successful pool registration, before the standard success toast/terminal state). Once-seen state is local storage via `FlowStorage.ts` — keys `joyjoin_flow_seen:v2:<flowId>:<userId>` (`prefix joyjoin_flow_seen`, version `v2`, `FlowStorageKind` = `joyjoin-intro` | `blind-box-lifecycle`). Version bump invalidates old seen flags. Shared shell: `FlowShell`; Flow 1 content: `JoyJoinPlayModeFlow`; Flow 2 content: `BlindBoxLifecycleFlow`; timeline visual: `AnimatedFlowTimeline` (+ `FlowStep`/`FlowNode`).

**Per-flow kill gates (2026-07-31):** DB-backed flags `flowIntroEnabled` (`FLOW_INTRO_ENABLED`, default `true`) and `flowLifecycleEnabled` (`FLOW_LIFECYCLE_ENABLED`, default `true`) in `apps/server/src/lib/featureFlags.ts`, resolved via the auth response `features` map. `false` suppresses the overlay entirely and routes users straight to the normal nextStep/success state. Rollback trigger: disable the flag if completion telemetry regresses or app-kill exceeds ~3%.

**Copy deck (2026-07-31):** All user-facing copy lives in `packages/shared/src/copy/flowAnimationCopy.ts` (PM-drafted, owner-approved, brand 🔴-compliant). Import via the explicit subpath `@shared/copy/flowAnimationCopy` — never the `@shared/copy` barrel (D12). No `.replaceAll()` in shared code (D13) — use `.replace(/{…}/g)`.

**Motion system (2026-07-31):** All timings in `flowAnimation.config.ts` `FLOW_ANIMATION_TIMING`: boxBeatMs 1200, bannerSettleMs 1200, entranceTotalMs 2400, experienceRevealMs 1200, lifecycleStageDurationsMs [800,1200,1200,1200,1200,1500] (≈7.1s total), boxApexMs 550, glowSweepStartMs 250, glowSweepDurationMs 600, completionHapticMs 850, ctaCrossfadeStartMs 950, ctaCrossfadeDurationMs 280, nodeTravelSettleMs 300, nodeRingFadeMs 240, progressTickMs 80. Flow 2 stage progress is driven by `useFlowTimeline.ts` (non-uniform dwell curve, `advance()` = one node per tap, `skip()`, `onStageLand`/`onComplete` callbacks; reduced-motion completes at start).

**Tap-ahead + analytics semantics (2026-07-31):** Whole-timeline tap-ahead (ONE node per tap) with a one-time ghost-pulse teacher; a `flow_tap_ahead` analytics event is tracked per tap. **Skip must never fire completion analytics** — `handleSkip` does not call `skip()` (which marks complete) and `trackSkip` is guarded pre-completion, so the skip metric counts early exits only and the completion metric stays truthful. Server whitelist in `apps/server/src/routes/domains/analytics.ts`: `flow_view`, `flow_skip`, `flow_cta_tap`, `flow_banner_tap`, `flow_detail_open`, `flow_detail_back`, `flow_node_tap`, `flow_tap_ahead`, `flow_complete` (+ `flow_street_gate_hit`).

**Personalization (2026-07-31):** FlowShell header shows an identity chip tinted with `getDeepContrastArchetypeColor()` (`packages/shared/src/archetypeColors.ts`, L clamp [22,32]) — `getContrastSafeArchetypeColor()` (L≤48) FAILS 4.5:1 on the white chip for warm archetypes (rooster ~2.7:1, cat ~2.3:1, corgi ~3.8:1); the deep variant passes all 12 (worst ≈5.06:1). Flow 1 experience detail crossfades between archetype banner backgrounds (`<Image mode='aspectFill'>` + scrim, keyframe `experience-scene-image-fade`) with the archetype full-body WebP from `ARCHETYPE_ASSET_MAP` (`lib/utils/archetypeAssets.ts`) as final frame. Banner URL canonical source: `lib/utils/flowBannerAssets.ts` (`FLOW_BANNER_ARCHETYPES`, `resolveFlowArchetypeBackgrounds`, `getFlowBannerPreloadUrls`, `isFlowCompanionArchetype`) — consumed by both FlowShell and `routePreloadAssets.ts` (`preloadFlowBannerBackgrounds`, also called from profile-review during the analyzing window once `primaryArchetype` is known). Banners are bundled locally under `assets/lovart/flow-archetype-backgrounds/` (bare `.webp`, no `@2x`/`@3x` suffixes) with CDN fallback via `cdnAsset()` (`flow-banner-{event|street}-{archetype}-v2.webp`).

**WeChat runtime rules (enforced by review, 2026-07-31):** rgba only (WXSS drops hsla); transform/opacity-only pulses (glow sweep animates `translateX`, never `left` — layout thrash); no nested `position: fixed` inside the fixed FlowShell (entrance overlay + glow are `absolute`); no CDN `background-image` in CSS (use `<Image>`); lid uses 2D translate/rotate (no perspective-safe `rotateX`). Reduced motion: box never mounts, all peaks collapse to ~150ms, haptics retained.

**Test coverage (2026-07-31):** `FlowStorage.test.ts` (seen-state isolation by flow/version/user), `useFlowTimeline.test.ts` (7 tests incl. the B1 regression: fresh-array durations must NOT restart the stage timer), `flowShellIdentityChip.test.ts` (3 tests: all 12 archetypes ≥4.5:1 on white, rgba format), `flowAnimationCopy.test.ts` (8 copy tests), server `flowAnalyticsRoutes.test.ts` (4). Known pitfall: an effect depending on the `stageDurationsMs` array REFERENCE restarts the stage timer every render (stage stuck at 0) — `useFlowTimeline` keys its effect on the content (`durationsKey = join(',')`).
