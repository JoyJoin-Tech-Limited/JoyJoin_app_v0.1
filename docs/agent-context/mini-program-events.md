# Mini-Program Events / Footprint — Agent Context

> Extracted from AGENTS.md §6 (2026-07-31). Load when working on the events tab, FootprintOracleCard, or pool-registration terminal states.

**Events / Footprint tab — FootprintOracleCard (2026-07-07):**
- **`FootprintOracleCard`** (`apps/mini-program/src/components/events/FootprintOracleCard.tsx`) — interactive event card for the "足迹" tab list. Wraps `EventSummaryCard` in a two-rail layout: left body carries the status pill, title, date/time/location; right rail carries a compact segmented countdown, group-size hint, price, or a "待公布" placeholder when none are available. Haptic feedback on tap; `hoverClass` pressed state; index-based entrance delay; reduced-motion/degradation tier disables entrance delay.
- **`EventSummaryCard`** (`apps/mini-program/src/components/events/EventSummaryCard.tsx`) — shared presentational base for `FootprintOracleCard` and any read-only confirmation surfaces (e.g. pool-registration terminal states). Renders the same gradient shell, status pulse pill, segmented countdown, title, date/time/location meta, and corner vignette. Supports `interactive` prop to toggle tap affordances and `railMode` + `rightRail` props for the two-rail layout. Title clamps to 2 lines with `keep-all` word breaking to avoid 孤字.
- **`SegmentedCountdownClock`** (`apps/mini-program/src/components/ui/SegmentedCountdownClock.tsx`) — reusable segmented countdown leaf extracted from `EventSummaryCard.tsx` (2026-08-27). Opt-in `externalNow` prop for external tick sources (gathering-room drives from its existing 60s interval); granularity props `showDays/Hours/Minutes/Seconds/Progress` default true. Consuming pages `@use` its SCSS (subpackage style-splitting rule). Used by `EventSummaryCard`, `FootprintOracleCard`, and the gathering-room floating pill.
- **`useEventCountdown`** (`apps/mini-program/src/hooks/useEventCountdown.ts`) — visibility-aware countdown hook returning `display`, structured `segments` (`days/hours/minutes/seconds/progress`), `isUrgent`, `hasStarted`, and `isLive`. Ticks are gated by in-viewport IntersectionObserver state, app hide/show lifecycle, `prefers-reduced-motion`, and `useDeviceTier().isDegradation`. The timer stops once `hasStarted` is true.
- **Venue disclosure rule:** Venue location is hidden after `报名成功`; it is disclosed only when the user-facing `displayStatus` is `confirmed` or `venue_unlocked`. The raw registration status `matched` means a group has been formed but the venue is still being assigned, so the card shows only event type + city/district. The server derives `displayStatus` from `matchStatus`, `poolStatus`, `venueAssignmentStatus`, and `venueName` in `apps/server/src/repositories/joinedEventsRepo.ts`; terminal pool states (`completed`/`cancelled`) override the registration-level status so finished or cancelled pools render correctly.
- **Two-rail accessibility:** The right rail itself is not `aria-hidden`; only the decorative `›` cue is hidden. `FootprintOracleCard` builds a `railAriaLabel` from the rail contents (countdown, group size, price) and appends it to the card's accessible name, so screen readers announce the same facts sighted users see.
- **Corner vignette text overlap (2026-07-21):** The Lovart event-type vignette is no longer avoided by text layers — all content (title, meta, badge) may flow over the light (opacity 0.5) vignette for a visually balanced card. Non-rail vignette enlarged from 220→280rpx; rail mode vignette stays at 168×168rpx (inside the right rail). OracleCard (`--has-corner-stat`) reserves only 120rpx for the solid corner-stat badge on the topline; all other layers flow full-width. Squad-unboxing event-brief vignette: repositioned to `absolute` top-right, 112→160rpx, date text flows underneath.
- **Terminal-state detection:** `FootprintOracleCard` consumes `isJoinedEventTerminal()` from `lib/utils/eventDisplay.ts` instead of maintaining its own status list.
- **`$font-mono` token (2026-06-28):** Added to `apps/mini-program/src/styles/_variables.scss` for monospace countdown digits. Use it for any numeric readout that needs tabular alignment.
- **`formatEventDateTime` enhancement:** Now renders `今天`/`明天`/`后天` prefixes for near-term event dates.
- **`getSystemReducedMotion()`** (`apps/mini-program/src/lib/utils/accessibility.ts`) — canonical helper for reading the OS-level reduced-motion preference. Prefer this over duplicating `Taro.getSystemInfoSync()` reads.
- **Accessibility:** The countdown clock uses `aria-live="polite"` so screen readers announce updates without overwhelming the user.

**桌友 Card-Deck UI (matching-status / pool-group-detail, 2026-08-16):**
- `TablemateCard` (`apps/mini-program/src/components/TablemateCard/index.tsx`) — reusable portrait card that borrows the squad-unboxing `TeammateCard` front-face recipe: archetype-tinted foil frame, 52% art zone / 48% info zone, 4-row face (avatar / name / archetype / meta / hook pill), connection-pill or pair-temperature chip, and skeleton shimmer in the archetype accent color. Used by the matching-status matched carousel and the pool-group-detail deck strip.
- `TablemateDetailSheet` (`apps/mini-program/src/components/TablemateDetailSheet/index.tsx`) — bottom-sheet member profile opened from any `TablemateCard` tap. Shows hero-image fade-in, avatar preview, full governed pair explanation with rarity-dotted connection points (`「…」` quoted), interest tags, industry line, and a `现场见` CTA. Supports drag-to-dismiss on the handle + hero, `catchMove` scroll containment, and reduced-motion instant landing.
- `pairChemistry.ts` (`apps/mini-program/src/lib/utils/pairChemistry.ts`) — shared display helpers extracted from squad-unboxing view-models: `scoreToChemistryType`, `getPairChemistryWord`, `getPairChemistryTier`, `CHEMISTRY_TIER_EMOJI`, `stripConnectionPointParens`, `shortenConnectionPointForPill`, `buildInterestHookText`. Keeps all 桌友 surfaces consistent without importing page-level view-models.
- **Entrance semantics:** `TablemateCard` supports a deal-in entrance (`dealt` + `entranceDelayMs`) and a surface-scoped `dealKey` session cache (`dealtOnceKeys`) so swipe-back does not replay the entire hand. `reduceMotion` lands cards instantly with no tilt/sheen.
- **Pool-group-detail deck strip:** horizontal `ScrollView` with real overflow measurement (`deckOverflows`), scroll-progress dots, a breathing "左滑看更多" hint until first scroll, and an `aria-label` describing the deck. The collapsed member list uses a `+N` chip and a left accent bar for the current-user row.
- **Subpackage move (2026-08-16):** `pages/pool-group-detail` moved out of the main package into its own subpackage (same precedent as squad-unboxing D1) after the deck reskin pushed main source size past WeChat's 2048KB upload gate. Preloads cover the entry surfaces (matching-status, center-hub, squad-unboxing, event-detail). The tablemate components no longer carry their own `import './index.scss'` — page SCSS `@use` owns style compilation so no duplicate copy lands in main-package `common.wxss`.

**Pool-registration terminal states (2026-06-30; success path replaced 2026-08-17):**
- **`PoolRegistrationTerminalStates.tsx`** (`apps/mini-program/src/pages/pool-registration/components/PoolRegistrationTerminalStates.tsx`) owns the loading (including the stale-deadline error card — the non-stale `LoadingScreen` renders inside `PoolRegistrationLoading`, not the page), empty/error, and already-joined states. The success state moved out (see below).
- **Already-joined screen** reuses `EventSummaryCard` so the event summary is visually identical to the "我的足迹" card; the success ceremony no longer uses it (the ticket carries the summary).
- **Read-only card mode:** terminal-state cards do not pass `interactive`, so they have no hover state, tap hint, or navigation.
- **Scroll safety:** terminal states wrap the centered card in `<ScrollView className='pool-reg__scroll'>` so the CTA and any follow-up content remain reachable on short phones.
- **Haptics:** primary CTAs use `haptics('medium')`; the secondary "开启匹配结果通知" button uses `haptics('light')`. The full registration-flow haptic/motion grammar lives in `docs/design/registration-ceremony-spec-20260817.md`.
- **Analytics:** terminal states emit `registration_terminal_state_view` on mount and `registration_terminal_cta_tap` / `registration_terminal_notify_tap` on tap.
- **Notification button state:** the parent page tracks `isEnablingNotifications` / `notificationsEnabled`; the button shows a loading spinner during the WeChat subscribe request and becomes disabled with "已开启提醒" after success.

**「订座」ceremony rework (P1, 2026-08-17):**
- **Unified success ceremony:** `RegistrationSuccessCeremony` (`apps/mini-program/src/components/reservation/`) is the single success surface for both pool-registration (standard variant, via the pool-specific wrapper `PoolRegistrationSuccessCeremony` that owns analytics + notify/pills/duo slots + `ChemistryMiniGrid` after-slot) and event-ticket-payment (`variant='paid'`, nav title 「报名成功」 and `event_ticket_payment_success_view` tracked at page level). It replaces `PoolRegistrationSuccess` and the deleted `TicketSuccessView` (confetti gone). The climax is a pure-CSS 「已留座」 seal stamp (scale-in 0.92→1.04→1.0, 320ms) with `socialHaptics('socialCelebration')` fired at the seal-land timestamp (one-shot per mount, immediate when motion is degraded); the paid variant adds a 票根 tear-off along the perforation (450ms). 「你是第 N 位入座的人」 uses real `registrationCount` only (hidden when 0/undefined). CTA is uniformly 「查看我的局」 on all registration success surfaces.
- **`ReservationTicket`** (same directory) is the shared slots-based ticket (banner/meta/perforation/footer, `card`/`flat` variants) consumed by the ceremony, the payment ticket card, and the confirm modal (`RegistrationConfirmModal`, flat variant, slimmed to meta + 24h-venue-disclosure + free-cancel rows; highlights as chips). Its TSX does not import its own SCSS — consuming subpackage pages `@use` it (style-splitting gate; selectors registered in `verify-subpackage-styles.mjs`).
- **3-step flow:** the in-page machine is 0 看场子 / 1 预算 / 2 期待+细节 (`STEP_DETAILS` removed; `resolveRegistrationStep` clamps legacy stored `resumeStep` ≥3 → 2). Step 0 is three beats: hero (with 「最近新增 N 位」 meta pill replacing the old banner) → `XiaoyueLetterCard` → duo single-row entry; persona snapshot/seat heads live behind the collapsed `PoolRegistrationVibePeek` expander, and optional details behind `PoolRegistrationDetailsExpander` on step 2 (酒局 alcohol comfort stays put — safety-relevant). `PoolRegistrationSummaryCard` and `PoolRegistrationNewRegistrantBanner` are deleted.
