**反馈激活与评价入口 (2026-10-16):**
- **Canonical rule:** feedback opens at event start +3h (`POOL_COMPLETION_BUFFER_MS` — the same buffer `poolCompletionSweep` completes pools on, so display state never fights the hourly sweep tick). `apps/server/src/lib/feedbackStateResolver.ts` is the single source of truth for all three event id families (pool / blind-box / events.id); the client never derives state from dateTime. Eligibility (D5): pool → `matchStatus ∈ {matched, completed}`; legacy → non-cancelled `event_attendance`. Test pools follow the same time rule (testers walk the full flow). **Window close (2026-11-11):** `closed` is now emitted at start + 7 days (`FEEDBACK_CLOSE_OFFSET_MS`); `POST /api/events/:eventId/feedback` answers 409 `FEEDBACK_WINDOW_CLOSED`, and the earlier `locked` case keeps 403 `FEEDBACK_NOT_OPEN`. `event_pools` has no duration column, so the open instant stays start + 3h (documented assumption). **Explicit absence (D-I2, 2026-11-11):** only an `event_attendance.attendance_status = 'absent'` row (self-report or admin override) makes a pool-family viewer ineligible; `pending`, `confirmed`, `late` and *no row at all* stay eligible — silence is never read as absence.
- **Endpoints:** `GET /api/events/:eventId/feedback-state` → `{ state: locked | open | submitted | ineligible | closed }` (404 unknown id; `{code:'server'}` on failure). `POST /api/events/:eventId/feedback` now runs eligibility → window → duplicate gates BEFORE content moderation, with coded 403/409s (`FEEDBACK_NOT_OPEN` / `FEEDBACK_NOT_ELIGIBLE` / `FEEDBACK_ALREADY_SUBMITTED`; copy in `packages/shared/src/copy/errorBaselines.ts`). The duplicate gate also closed a pre-existing XP double-award loophole.
- **Event-detail action bar** (`pages/event-detail/`, redesign): brand-standard fixed bottom bar (white surface + top shadow + safe-area; ScrollView flex sibling — not `position:fixed`), `__cta` system with `--live` (进入破冰: solid purple + 👥 white chip + 12rpx breathing dot, opacity/scale only), `--locked` (明确灰 but TAPPABLE — toast teaching + `feedback_locked_tap`; never native `disabled`, which would swallow the tap), `--done` (已评价, white + green hairline + ✓). Copy: 提交反馈 → 去评价 / 已评价. At most ONE solid-primary CTA on screen (live → 进入破冰; post-event → 去评价); when a still-live event crosses the +3h gate (blind-box `ongoing`), 去评价 demotes to the `--secondary` outline instead of a second solid fill. Fail-closed: when the feedback-state query fails, the feedback entry hides entirely. Pool liveness is time-based (2026-10-16 fix — see the 进入破冰 window bullet below). Invariants source-locked in `pages/event-detail/__tests__/eventDetailPage.test.ts`.
- **Feedback page gate** (`pages/event-feedback/`): loads feedback-state itself; locked/ineligible/error render `__gate` StatusCards; `submitted` derives `effectiveStep` at render time straight into the thanks state (no form flash). `from` param whitelist (`event_detail` / `events_tab` / `recap_push` / omitted) feeds `feedback_page_open`. Post-submit busts joined-events + events shell + feedback-state caches (otherwise the 足迹 pill lingers behind staleTime).
- **足迹 entry (no-grant fallback):** `JoinedEventSummary.feedbackPending` is derived server-side in `joinedEventsRepo.ts` (explicit pool→group→canonical-event mapping — never the pool id itself; batched existence query, no N+1) and drives the `FootprintOracleCard` 「去评价」 pill (secondary brand pill, not solid purple; `stopPropagation`; supersedes the `›` cue). This is the in-app fallback for users without a subscribe-message grant; the recap push deep-links to the same page.
- **Analytics:** `feedback_entry_shown` (state + surface), `feedback_locked_tap`, `feedback_reminder_tap`, `feedback_page_open` (source) — client union in `lib/analytics/feedbackAnalytics.ts`, server whitelist in `routes/domains/analytics.ts`, parity locked by `feedbackAnalyticsAllowlistContract.test.ts`.
- **Optional felt-heard item (2026-11-09, flag default OFF):** `feedbackAcknowledgmentItemEnabled` adds the five-point 「今晚，我的发言有被同桌接住」 question to the experience screen (untouched = unanswered, never 0). The score is **not** part of the canonical `POST /api/events/:eventId/feedback` payload; it is emitted as `feedback_acknowledgment_submitted` only after the canonical POST succeeds and only while the flag is still ON. A 409 `FEEDBACK_ALREADY_SUBMITTED` or an unanswered item emits nothing.
- **进入破冰 window (2026-10-16 fix):** the CTA used to be gated on `status ∈ {started, active, ongoing}` — a set the server never writes for pool events (pools go `active` → `matching` → `matched` → `completed`), while a group id resolves only AFTER matching. The pool CTA was therefore unreachable in production; the only pool that ever showed it was a test pool parked on `active` with a single-test group. Pools now use a dateTime window `[start − 1h, start + 3h]` (`apps/mini-program/src/lib/utils/eventLiveWindow.ts`; the +3h tail mirrors `POOL_COMPLETION_BUFFER_MS`, so 进入破冰 hands the bar to 去评价 instead of the two coexisting; `cancelled`/`archived` never open, missing/unparseable dateTime fails closed). The joined-events query (group id source) is enabled only while that window is open. Blind-box events keep the status gate; boundaries pinned in `eventLiveWindow.test.ts`, wiring source-locked in `eventDetailPage.test.ts`.
