Both verb and address run 24rpx (measured 4.48:1 at 22rpx; this is the string read aloud to a driver) and the verb uses `$color-primary-dark`, since `$color-primary` on the lower surface measures 4.0:1. It is demoted rather than removed on terminal cards — name, address and a quiet plate stay as the record (a bare verb on a transparent field read as stray link text in the render) — and a **finished record always shows where it happened** (2026-11-17): `showResolvedPlace = showVenue || isHistoricalNonterminal`, so a past pool whose match status was never swept to terminal (the path that renders the 已结束 pill) no longer suppresses the venue it already knows. It falls back to the raw address if the strip would leave fewer than 3 characters. **Verb rides the venue name's line (2026-11-17):** `__place-head` holds `__place-primary` (`flex: 1; min-width: 0`) beside `__place-action`, so a long venue truncates before the verb can be pushed out of the border, and the street below spans the full plate (clamped at two lines — `广东省深圳市福田区福华五路卓越世纪中心 4 栋 2 楼` does not fit 348rpx). With the verb as a flex sibling of `__place-body` it centred itself against a two-line address and carved ~120rpx out of both lines: 「东门老街解放路 / 1 号 2 楼」 wrapped around a verb floating in the gutter. A terminal card that still carries a verb keeps a quiet plate (`__place--actionable`: `rgba($color-surface, 0.42)` fill + `rgba($color-primary, 0.1)` border, declared **after** the terminal transparent rule so source order wins) — the record is finished, the tap target is not. **Venue-lands beat:** `FootprintOracleCard` watches `pending → resolved` via a ref seeded with the first render, so a card that opens already-resolved never celebrates; a transition seen by the mounted card sets `placeRevealed` → `__place--revealed` (300ms `footprint-place-reveal`, transform + opacity only) and fires `haptics('success')` once. The theme value itself moved from 24rpx system to **28rpx `font-cn-display` semibold** while the `主题` label dropped to normal weight + 0.08em tracking — the label recedes so the table's name carries the line, and the value stays strictly under the 40rpx bold title. Never a provenance sentence (`由…生成` is a 🔴 brand hard rule), never a score (collides with `合拍度`), and suppressed entirely on sealed cards. Server adds `themeSubtitle` / `themeHighlights` to the `poolRows` select; `__venue` and the `matched`/`confirmed`/`venue_unlocked` waiting lines are deleted. **Theme title is clamped server-side** (`apps/server/src/lib/themeTitleClamp.ts`, 11 graphemes) on write (`matchPersistence`, LLM `saveGroupTheme`) and again on read (`joinedEventsRepo`), because 12 CJK glyphs already consume the 338rpx value column exactly and a display-size name ellipsized by the UI is the worst failure this element can have. The clamp keeps the head clause of a compound title (`高能充电站：柯基×狐狸的周末探险` → `高能充电站`) rather than cutting mid-phrase, and never appends its own ellipsis; the generator prompt now also forbids `·`/`:`/dash compounds. **反馈激活与评价入口 (2026-10-16):**
- **Canonical rule:** feedback opens at event start +3h (`POOL_COMPLETION_BUFFER_MS` — the same buffer `poolCompletionSweep` completes pools on, so display state never fights the hourly sweep tick). `apps/server/src/lib/feedbackStateResolver.ts` is the single source of truth for all three event id families (pool / blind-box / events.id); the client never derives state from dateTime. Eligibility (D5): pool → `matchStatus ∈ {matched, completed}`; legacy → non-cancelled `event_attendance`. Test pools follow the same time rule (testers walk the full flow). **Window close (2026-11-11):** `closed` is now emitted at start + 7 days (`FEEDBACK_CLOSE_OFFSET_MS`); `POST /api/events/:eventId/feedback` answers 409 `FEEDBACK_WINDOW_CLOSED`, and the earlier `locked` case keeps 403 `FEEDBACK_NOT_OPEN`. `event_pools` has no duration column, so the open instant stays start + 3h (documented assumption). **Explicit absence (D-I2, 2026-11-11):** only an `event_attendance.attendance_status = 'absent'` row (self-report or admin override) makes a pool-family viewer ineligible; `pending`, `confirmed`, `late` and *no row at all* stay eligible — silence is never read as absence.
- **Endpoints:** `GET /api/events/:eventId/feedback-state` → `{ state: locked | open | submitted | ineligible | closed }` (404 unknown id; `{code:'server'}` on failure). `POST /api/events/:eventId/feedback` now runs eligibility → window → duplicate gates BEFORE content moderation, with coded 403/409s (`FEEDBACK_NOT_OPEN` / `FEEDBACK_NOT_ELIGIBLE` / `FEEDBACK_ALREADY_SUBMITTED`; copy in `packages/shared/src/copy/errorBaselines.ts`). The duplicate gate also closed a pre-existing XP double-award loophole.
