## 1. 执行摘要（≤200字）

**Q1：差异化优势足够吗？** 在核心体验层（匹配引擎深度、现场破冰系统、活动前集结房间、付费结构）我们结构性领先，且破冰系统是最深护城河——对方短期内无法复制。但在**付费决策点的信任密度**（详情页无流程时间线/FAQ/UGC）和新客预售叙事上，T46 明显更成熟。表面差异（盲盒叙事、mascot 陪伴、邀请函仪式）实则同质。

**Q2：要不要做新手指引？** 不做 T46 式 2 分钟模拟聊天——那是他们没有真实前置体验的代偿品，我们的匿名性格测试+老虎机揭晓就是更强的"真实预售"。**要做的是付费前信任三件套补齐**（详情页怎么参加/FAQ/退款理由叙事），S/M 级，直接抬转化。

### 表面差异实则同质（别自我陶醉）

- **盲盒叙事**：他们「地点故意模糊（市中心某酒吧）」，我们「排桌完成前地点待定」。同质。
- **mascot 陪伴**：小盒子 vs 悦仔。我们更强（悦仔全链路声纹矩阵 `onboardingVoice.ts` 84 条、破冰 toneLine），但「有 mascot」本身不是差异。

## 3. 差异化优势判定：真护城河 vs 伪差异

### 真护城河（对方 6 个月内追不上）

1. **Social Icebreaker 现场系统**——phase 状态机 + host 权威 + LLM 硬边界管线 + tier/vibe 编译 + 高光/glow 元游戏。单「mini_script 剧本杀」一项就有 28s pipeline 超时、双轮投票、reaction 服务器门控等厚度。对方卡牌是道具，我们是系统。
2. **12 原型 V4 自适应测评 + 磁场引擎**——测评本身是获客钩子（匿名可测），评分是确定性服务器权威。对方的问卷在付费墙后，既无前置体验价值也无可见的组桌规则。
3. **集结房间**——活动前的期待工程，独有。
4. **悦聚卡定价结构**——¥98/6场对 ¥88/场是降维。这不是"更便宜"，是把品类从"买单场体验"改写为"订阅一种周末生活方式"。

### 伪差异（别再拿来说服自己）

- 「我们有 mascot 他们没有」——他们有，叫小盒子。
- 「我们是盲盒」——他们也是，且地点模糊做得更彻底。
- 「我们有仪式感」——双方都有，我们的赢在产出真实资产而非纯表演，这个细节才值得说。
- 「我们更懂年轻人」——无法证伪的话不要写进任何文档。

### 对方真实领先（认账才能赢）

1. **付费决策点的信任工程**：流程时间线+FAQ+UGC+退款理由叙事，四位一体。我们详情页只有信息卡+客服卡。
2. **「身份解锁」叙事钩子**：一句话讲清、情感峰值集中。我们的后链路功能更强但没有一个同样锋利的句子。
3. **供给节律化**：固定场次降低决策成本，零代码可抄。
4. **预售对未注册用户开放**：他们的 Discover 游客可见（活动卡+价格+指引入口都在）；**我们的 Discover 对游客直接渲染 LandingPage**（`discover/index.tsx:1179`），游客连一场局的真实样子都看不到——所有的解释压力都压在 landing 一句话上。

## 4. 新手指引决策：不做 T46 式模拟，做「首局预告片 + 信任三件套」

### 判定：不做聊天式模拟指引，但要做付费前的认知/信任补齐

**为什么不做 T46 那种 2 分钟模拟聊天：**

1. **它是代偿品，不是优势本身。** T46  funnel 是「先看局 → 付款 → 才填问卷」，付费前用户手里没有任何真实资产，所以必须模拟一个情感弧线来预售。我们的 funnel 是「landing → **匿名性格测试（免费、真实、有产出）** → 老虎机揭晓原型 → 登录 → onboarding → discover」（`anonymousOnboarding` 匿名测评链路真实存在：`assessmentV4.ts:249`、`personality-test/index.tsx`）。**我们的预售是真实产品体验，他们的预售是广告片。** 照抄广告片反而稀释我们"测完就知道自己是谁"的独特峰值。
2. **历史证据：我们两次删掉机制解释层。** Flow 1 intro overlay（2026-08-26 删，并入 Discover arrival coachmark）、landing 机制条「①答小题②攒一桌③见真人」（2026-09-03 删，因与 hero 图像重复）。两次结论一致：解释要折进仪式和内容，不做独立教学层。这不是说不解释，而是说**单独做一个模拟流程在我们这里已经被实践证明会冗余**。
3. **微信审核红线收窄了"直接说明"的空间。** T46 文案「6 人精准匹配」我们写不了——🟠「匹配」仅限"匹配偏好/设置"语境，🔴 禁止解释机制（"系统为您推荐/算法"），可见文案词表是排桌/合拍度/攒一桌/入座（brand-copy-strategy §2/§3 + AGENTS.md 微信审核姿态）。照抄他们的指引文案直接过不了审。

**但我们有一个真实缺口必须补：** 游客看不到任何"局"的真实样子（价格、流程、退款、现场感），而首次付费决策点（详情页/收银台）的信任密度不足。T46 在这个点上的工程完整度确实领先。

### 要做的形态（不是照抄，是长在我们结构上）

| 模块 | 内容 | 入口/时机 | 工作量 |
|------|------|----------|--------|
| **A. 详情页「怎么参加」区块** | 4 拍流程条：订座 → 悦仔排桌 → 集结房间等开席 → 现场入座（合规词，不出现 匹配/算法）；常驻、可折叠 | 详情页信息卡下方，对所有用户可见 | **S**（纯前端策展内容，复用现有插画资产） |
| **B. 详情页 FAQ 手风琴** | 6-8 条：一个人来会不会尴尬 / 不喝酒可以吗 / 同桌是怎么攒的（"悦仔按你们的画像排桌"，🟠合规）/ 地点什么时候公布 / 临时来不了怎么办（排桌完成前全额退款）/ 可以和朋友一起吗（双人成行） | 详情页 FAQ 区 + 客服卡已有 | **S**（文案需过 brand-copy 🔴🟠 审） |
| **C. 收银台退款理由叙事** | 现有「排桌完成前取消，全额退款」保障行升级为"理由叙事"：为什么排桌后不退——"这一桌已经写上你的名字，桌友在等你"（对齐 T46"已开始定制物料"的叙事手法，用我们的排桌语义） | 收银台 + RegistrationConfirmModal | **XS**（纯文案） |
| **D. 「首局预告片」轻内容层** | 一次性 Discover arrival coachmark 升级扩容：3-4 屏静态/轻动效，用**我们自己的真实资产**（集结房间截图、桌友卡、破冰现场、recap 金句）讲"一场局的四拍"；可跳过、可在「我的 → 帮助」重看 | 首次进 Discover（现有 coachmark 机制扩容）+ 我的页常驻入口 | **M** |
| **E.（可选）登录墙前预告** | 匿名测评完成→揭晓原型后、要求登录前，加一屏"你这样的原型，上周进了这样的局"（真实数据驱动：近 7 天成局数，🔴 禁止虚构数字；无数据则省略指标只讲价值） | 测评结果页与登录之间 | **M**（需评估是否拉长登录路径，A/B 后再定） |

**与现有 onboarding 的边界：** 以上全部是**内容层**，不碰 server-driven nextStep 结构（setup → extended → review → discover 不动），不加流程步骤，不阻塞 CTA。onboarding 的职责是收集画像+建立仪式，首局预告片的职责是建立"这是什么局"的具体想象——两者不重叠。

**审核合规约束（硬）：** 全文案禁用 匹配/社交/灵魂/AI/算法/精准匹配；排桌/攒一桌/合拍度/入座词族；社会证明只许 live query 真实数字或省略（🔴）；AIGC 角标 fail-closed 原则不适用此处（内容全策展）。

## 5. 狼性收尾：偷什么、不跟什么

### 最值得偷的 3 招（按 ROI 排序）

1. **详情页信任三件套（上面 4.A+4.B）——P0，S 级，本周可排。** 对方用 4 步时间线+FAQ 把"6 个陌生人吃饭"的焦虑逐条拆解，我们详情页现在只有时间/地点/人数/状态四行信息。这是转化漏斗上最便宜的提升点，纯前端、零风险、不碰任何引擎。UGC 用户心声我们暂时没有素材积累，**不造假照片墙**（🔴 红线）——替代：用真实 recap 金句（破冰 recap 已有产出口碑文案的数据管线）做"往期这一桌"区块。
2. **收银台退款理由叙事（4.C）——P0，XS 级。** T46 把扣费理由（"已开始定制物料"）写在收银台，把争议化解在付费前。我们的退款政策（排桌前全额退/排桌后不退）比他们的 28h 分界更简单更厚道，但**没人知道**——政策躺在条款里，保障行没有理由。一句话的事。
3. **供给节律化——运营动作，零代码。** 固定"每周三/周六晚局"，降低"什么时候有"的认知成本，同时给订阅消息和复购一个节律钩子。T46 已验证，深圳首发运营直接抄排期。

### 不该跟的坑（他们会疼，我们别跟着疼）

1. **先付款后填问卷——不跟。** 他们把最贵的动作放最前面，再用 2 分钟广告片硬垫信任，这是 funnel 结构缺陷的补丁。我们"先给真实测评资产、后谈钱"的心理账户顺序更健康，转化率压力不该用付款前置来解——那会摧毁测评即预售的差异化，还把退款率压力拉满。
2. **真人审核流水线——不跟。** 重运营、低吞吐。微信实名+平台支付闭环+真人到场核销已构成反诈底座，把这件事**写进信任文案**（"平台支付闭环，真人到场核销"）比建审核团队便宜一百倍。
3. **群聊作为沉淀终点——不跟，但偷其叙事节奏。** 群聊解锁后关系沉在微信生态里，平台价值被抽干；我们的连接 tab 结构化沉淀才是复利。但他们的"解锁时刻"提醒我们：我们活动后缺一个集中的第二层揭晓钩子。建议低优先级探索：互选成功时刻的"真人揭晓"仪式感（现状互选只是通知），把连接建立做成一个峰值而非一条通知。
4. **虚构社会证明——永不跟。** "3万+人赴约"出现两次是他们的增长润滑剂，是我们的审核红牌（🔴）。我们的武器是真实数字的 live query（"已有 N 人入座"），少一点冲击力，多十分可信。

### 6.2 Q-A~Q-E 逐条裁决

- **Q-A 范围冻结（若只许上一周班，砍哪个）**：砍 P0 埋点基线的「等待」，不砍任何交付物。三件套排序：退款承诺-行为 gap 修复（开 flag + 理由叙事）> 详情页时间线+FAQ > 埋点。理由：gap 是现存信任事故级风险（文案已承诺退款、代码不退款），它不是转化优化是止血；时间线/FAQ 是行业基准及格线；埋点可以晚一周，gap 不能多活一周。
- **Q-B 游客视野：做，但位置收窄到「匿名测评结果页 → 登录墙之间」，Discover 保持登录墙。** 三个理由：(1) T46 开放 Discover 是因为他们没有别的游客钩子，我们有——匿名测评（`assessmentV4.ts:249` 匿名会话恢复）给游客真实资产（原型+老虎机仪式），游客转化焦虑的峰值在「测完看到自己是誰」之后，不在浏览列表时；(2) Discover 是全功能页（报名/提醒/集结全依赖 auth），游客化要动 shell 接口+池卡交互降级+审核面扩大，ROI 不成立；(3) landing 是 locked 100dvh 零滚动政策（viewport-zero-scroll 技能），加不了内容。形态：结果页后插入 2-3 张**真实场次只读卡**（标题/时间/区域/¥88 起，无报名交互）+「微信登录，为你留座」钩子；供给门槛 ≥3 场才渲染（🔴 真实数字红线，供给少时渲染=露怯）。量级 M（3-4 人天，复用池卡组件 + guest-safe 只读接口）。首局预告片主展示点同步移到此处 + 详情页三件套；Discover 首访 coachmark 保持现有轻量形态不扩容。
- **Q-C 双人同行形态：邀请制前置收银台，否决一人代付两座。** UX 理由：我们的信任结构是「每个人都是被测评过的画像」——代付两座的第二人没有测评、没有画像，排桌引擎（6D 评分 + Duo 原子单位规则，`poolMatchingService.ts` [DUO] guards）拿到的输入是残缺的，要么现场凑出一个无画像座位（排桌质量塌方），要么事后再逼被邀请人补测评（链路比邀请制更长且体验更差）。T46 能代付是因为他们付款在问卷前；我们测评前置，代付是伪捷径。邀请制的「多一跳」不是漏斗损耗：第二人完成注册+测评 = 新增一个完整用户（LTV 归属清晰）+ ¥50 INVITE_REWARD 钩子（migration 0098 已 seed）。收银台落地形态：一行「和朋友一起？邀 TA 同行，排进同一桌」入口 → 跳 Duo 邀请链路（`routes/domains/duo.ts`），文案挂「同行有奖励」回引——同意 CEO 风险 3 的处理。
- **Q-D 第二层揭晓（互选真人揭晓仪式感）：归档，现在不立项。** 它是付费后链路优化，本轮资源必须集中在付费前信任（P0 止血+及格线）；且「真人揭晓」涉及照片/真名隐私设计与内容政策，需要独立 PRD，不该搭这波车。触发条件写明：连接 tab 互选率基线建立（埋点先行）+ P0/P1 全部落地后，由 draft-prd 单独立项。
- **Q-E 供给节律：内部运营承诺现在生效，用户可见承诺连续 4 周供给达标后再写进文案。** 深圳 venue 白名单缺口是已知 blocker（dining 档无餐厅，商业化备忘录自己也写了「先补 venue 再放量」）；供给没稳住就把「每周三/六」写进 FAQ/预告片 = 制造违约风险，违约比无承诺更伤信任。FAQ 措辞用「每周都有局」软表述，运营排期内部对齐周三/周六心智。

### 6.3 对 CEO 备忘录的挑战

1. **「退款是现行默认行为，灰度不动」——事实错误，推翻。** `computeRegistrationCancelPolicy` 在双 flag 均关时返回 undefined（`poolRegistrationCancel.ts:118`），取消走 legacy 分支只删 row + 减计数、不退款。收银台承诺与生产行为**此刻就不一致**。这不是要不要展示政策的问题，是要不要先兑现已经展示的承诺。裁决：P0 退款叙事的前置 = 开 `preRevealRefundEnabled`（本来就是 PRODUCT_REQUIREMENTS.md:1241 既定上线顺序的第一步，法务条款已对齐 v2026-08-27），灰度必须动。
2. **「60-90 秒首访预览卡」——时长砍到 15-30 秒可扫读，且移位（见 Q-B）。** 把 2 分钟预售放给已完成测评+onboarding 的用户，是误读了 T46 指引的存在理由：他们预售是因为游客手里没有任何真实资产；我们的首访 Discover 用户手里已经有原型、入场卡、欢迎券。给已转化用户重播广告 = 打扰。CEO 自己的护栏 2（跳过率 ≤60%）其实已经在怀疑这件事——我直接把它修掉：主展示点不在 Discover。
3. **「全部走 flag 灰度」——收窄灰度范围。** 时间线+FAQ 是纯静态策展内容（无引擎、无数据依赖、行业基准组件），全量上线不灰度；灰度预算只留给两个真正有行为风险的改动：收银台退款叙事（50/50 观察 7 天取消率，同意 CEO 风险 2）与结果页游客预告卡。「全部灰度」不能成为拖延及格线组件上线的借口。
4. **埋点基线串行等待 2 周——并行化（见草案裁决行 3）。** 北极星定义（详情页→收银台转化）同意；但基线是判定工具不是上线闸门。
5. **上海话术「含破冰主持」——措辞推翻。** 破冰是桌友之一担任 host 的 host-paced 流程（`social-icebreaker-domain`），不是平台派主持人；「含破冰主持」暗示平台提供服务人员 = 虚假承诺 + 审核风险。改为「一场有节奏的夜晚」类体验描述，且任何对外话术不提竞对、不做对比广告。
